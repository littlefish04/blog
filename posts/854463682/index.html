    一、支持变长栈帧

    到目前为止，我们检查过的各种函数的机器级代码都有一个共同点：编译器能够预先确定需要为栈帧分配多少空间。但有些函数需要的局部存储是变长的。例如，当函数调用 alloca 时就会发生这种情况——alloca 是一个标准库函数，可以在栈上分配任意字节数量的存储；当代码声明一个局部变长数组时，也会发生这种情况。

    虽然本节介绍的内容实际上属于过程实现的一部分，但我们还是把它推迟到现在才讲，因为它需要用到数组和数据对齐的相关知识。

    二、浮点代码

    2.1 媒体寄存器

    简要回顾一下历史，会对理解 x86-64 的浮点体系结构有所帮助。1997 年出现了 Pentium/MMX，此后 Intel 和 AMD 都引入了持续数代的媒体（media）指令，用以支持图形和图像处理。这类指令的本意是允许多个操作以并行模式执行，称为单指令多数据（SIMD，读作 sim-dee），即对多个不同的数据并行执行同一个操作。近年来，这些扩展有了长足的发展，名字也经过了一系列大的修改：从 MMX 到 SSE（Streaming SIMD Extension，流式 SIMD 扩展），再到最新的 AVX（Advanced Vector Extension，高级向量扩展），每一代中还有一些不同的版本。每个扩展管理的都是一组寄存器中的数据，这些寄存器组在 MMX 中称为 MM 寄存器，SSE 中称为 XMM 寄存器，而在 AVX 中称为 YMM 寄存器；MM 寄存器是 64 位的，XMM 是 128 位的，而 YMM 是 256 位的。所以，每个 YMM 寄存器可以存放 8 个 32 位值，或 4 个 64 位值，这些值可以是整数，也可以是浮点数。

    2000 年 Pentium 4 中引入了 SSE2，媒体指令开始包括那些对标量浮点数据进行操作的指令，也就是对单个数据值进行操作，使用 XMM 或 YMM 寄存器的低 32 位或 64 位中的单个值。这种标量模式提供的一组寄存器和指令，更类似于其他处理器支持浮点数的方式。所有能够执行 x86-64 代码的处理器都支持 SSE2 或更高的版本，因此 x86-64 的浮点数是基于 SSE 或 AVX 的，包括传递过程参数和返回值的规则。

    我们的讲述基于 AVX2，即 AVX 的第二个版本，它是在 2013 年 Core i7 Haswell 处理器中引入的。当给定命令行参数 -mavx2 时，GCC 会生成 AVX2 代码。基于不同版本 SSE 以及第一个版本 AVX 的代码从概念上来说类似，只是指令名和格式有所不同。我们只介绍用 GCC 编译浮点程序时会出现的那些指令，其中大部分是标量 AVX 指令；对整个数据向量进行操作的指令出现时，我们也会说明。

    如图 3-45 所示，AVX 浮点体系结构允许把数据存储在 16 个 YMM 寄存器中，它们的名字为 。每个 YMM 寄存器都是 256 位（32 字节）。当对标量数据操作时，这些寄存器只保存浮点数，而且只使用低 32 位（对于 float）或 64 位（对于 double），汇编代码用寄存器的 SSE XMM 寄存器名字 来引用它们，每个 XMM 寄存器都是对应 YMM 寄存器的低 128 位（16 字节）。

    2.2 浮点传送和转换操作

    传送指令

    图 3-46 给出了一组在内存和 XMM 寄存器之间以及从一个 XMM 寄存器到另一个 XMM 寄存器传送浮点数的指令：

    指令 源 目的 描述
    vmovss X 传送单精度数
    vmovss X 传送单精度数
    vmovsd X 传送双精度数
    vmovsd X 传送双精度数
    vmovaps X X 传送对齐的封装好的单精度数
    vmovapd X X 传送对齐的封装好的双精度数

    其中，有一个操作数引用内存的指令是标量指令，意味着它们只对单个而不是一组封装好的数据值进行操作。GCC 只用标量传送操作从内存传送数据到 XMM 寄存器，或从 XMM 寄存器传送数据到内存。数据要么保存在内存中（由表中的 和 指明），要么保存在 XMM 寄存器中（在表中用 X 表示）。无论数据对齐与否，这些指令都能正确执行，不过代码优化规则建议 32 位内存数据满足 4 字节对齐，64 位数据满足 8 字节对齐。内存引用的指定方式与整数 mov 指令的一样，包括偏移量、基址寄存器、变址寄存器和伸缩因子的所有可能的组合。

    对于在两个 XMM 寄存器之间传送数据，GCC 会使用两种指令之一，即用 vmovaps 传送单精度数，用 vmovapd 传送双精度数。对于这些情况，程序复制整个寄存器还是只复制低位值，既不会影响程序功能，也不会影响执行速度，所以使用这些指令和使用针对标量数据的指令，其实没有实质上的差别。指令名字中的字母 a 表示 aligned（对齐的）。当用于读写内存时，如果地址不满足 16 字节对齐，它们会导致异常；不过在两个寄存器之间传送数据，绝不会出现错误对齐的状况。

    2.3 浮点数做参数和返回值

    在 x86-64 中，XMM 寄存器用来向函数传递浮点参数，以及从函数返回浮点值。如图 3-45 所示，可以看到如下规则：

    2.6 位级操作和比较操作

    位级操作指令

    有时，我们会发现 GCC 生成的代码会在 XMM 寄存器上执行位级操作。图 3-50 展示了一些相关的指令，类似于它们在通用寄存器上对应的操作。这些指令对两个源寄存器的所有位都实施指定的位级操作，然后更新整个目的 XMM 寄存器。和前面一样，我们只对标量数据感兴趣，只想了解这些指令对目的寄存器的低 4 或 8 字节的影响。运用这些操作通常可以简单方便地操作浮点数。

    单精度 双精度 效果 描述
    vxorps vxorpd D ← S2 ^ S1 位级异或（EXCLUSIVE-OR）
    vandps vandpd D ← S2 & S1 位级与（AND）

    比较指令和条件跳转

    AVX2 提供了两条用于比较浮点数值的指令：

    指令 基于 描述
    ucomiss 、 比较单精度值
    ucomisd 、 比较双精度值

    这些指令类似于 cmp 指令（参见 3.6 节），它们都比较操作数 和 ，并且设置条件码指示它们的相对值。与 cmpq 一样，它们遵循以相反顺序列出操作数的 ATT 格式惯例。参数 必须在 XMM 寄存器中，而 可以在 XMM 寄存器中，也可以在内存中。

    浮点比较指令会设置三个条件码：零标志位 ZF、进位标志位 CF 和奇偶标志位 PF。3.6.1 节中我们没有讲奇偶标志位，因为它在 GCC 产生的 x86 代码中不太常见。对于整数操作，当最近的一次算术或逻辑运算产生的值的最低位字节是偶校验的（即这个字节中有偶数个 1），那么就会设置这个标志位；不过对于浮点比较，当两个操作数中任一个是 NaN 时，会设置该位。

    条件码的设置条件如下：

    顺序 CF ZF PF
    无序的 1 1 1
    1 0 0
    0 1 0
    0 0 0

    当任一操作数为 NaN 时，就会出现无序的情况，可以通过奇偶标志位发现这种情况。通常用 jp（jump on parity）指令来做条件跳转，其条件就是浮点比较得到了一个无序的结果。除了这种情况以外，进位和零标志位的值都和对应的无符号比较一样：当两个操作数相等时，设置 ZF；当 时，设置 CF；像 ja 和 jb 这样的指令可以根据标志位的各种组合进行条件跳转。

    OpenGL 入门学习（一）

    写在前面

    在学习 Unity 渲染管线时，我感到十分吃力，许多概念如同天书一般难以理解。经过一番搜索，我发现 Unity 的渲染管线本质上是对 OpenGL 的封装——直接学习 OpenGL 反而能让学习曲线更加平滑，于是决定从这里开始入门图形学。

    笔者使用的是 Windows 系统，博客里的所有操作均在 Windows 系统下完成。理论上我参考的教程也可以在 macOS 上完成，但该博客不涉及相关知识。

    部分内容为ai生成，如有错误恳请指出。

    一、什么是 OpenGL

    OpenGL 本质上是一个规范（Specification），它定义了一系列接口，开发者通过这些接口可以操作 GPU 完成图形渲染工作。

    所谓接口，通俗来说就是规定了函数的名称、接收的参数、返回值以及函数的作用——它只告诉你”能做什么”和”怎么调用”，而不暴露内部的实现细节。对于调用者而言，只需要知道接口的定义就能使用，完全无需关心底层是如何实现的。

    OpenGL 仅仅是一份规范，本身并不包含任何函数的具体实现。真正的实现代码在哪里呢？答案是在 GPU 驱动中，由各个 GPU 厂商（如 NVIDIA、AMD、Intel 等）自行完成。当我们调用 OpenGL API 时，实际执行的是厂商在驱动层编写好的函数。

    由于不同厂商的实现方式各不相同，同一段 OpenGL 代码在不同平台上的表现可能会出现差异。比如某段代码在 NVIDIA 显卡上运行良好，在 AMD 显卡上却可能出现意料之外的 Bug。此外，大部分 GPU 厂商并不会开源自己的驱动代码，因此开发者通常无从得知这些函数底层的具体实现细节。

    OpenGL 的跨平台特性

    既然 OpenGL 只是一套接口规范，具体实现由各个平台的厂商分别完成，那么它的跨平台特性就很好理解了：只要某个平台实现了 OpenGL 规范，OpenGL 代码就能在该平台上运行。

    对于个人开发者而言，使用 OpenGL 可以方便地将应用发布到多个平台。不过需要注意的是，许多平台对 OpenGL 的实现质量并不如其原生图形 API——底层的驱动优化可能不够充分、接口使用起来也不够便捷。因此，对于大型游戏项目来说，针对不同平台分别使用各自的原生图形 API（如 Windows 上的 DirectX、Apple 平台上的 Metal）也是常见的做法。

    为什么学习 OpenGL

    你可能也听说过其他图形 API，比如 DirectX、Vulkan 等，或许还了解到这些 API 在某些方面性能更好、功能更强。那么为什么仍然选择从 OpenGL 入门呢？

    除了前面提到的——Unity 的渲染管线封装自 OpenGL——另一个重要原因是：OpenGL 在一众图形 API 中是相对最简单的，非常适合初学者作为图形学入门的起点。

    此外，许多其他图形 API 在设计上也会提供对 OpenGL 概念的兼容或封装，学好 OpenGL 所打下的基础，在后续学习其他图形 API 时同样用得上。

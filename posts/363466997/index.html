    一、字节、字长与字节顺序

    1.1 字节与虚拟地址空间

    大多数计算机使用 8 位的块——字节（byte）——作为最小的可寻址内存单位。机器级程序将内存视为一个非常大的字节数组，称为虚拟内存（virtual memory）。内存中的每个字节都由一个唯一的数字标识，这个数字称为它的地址（address），所有可能地址的集合就称为虚拟地址空间（virtual address space）。

    在接下来的几章中，我们将看到编译器和运行时系统如何把存储空间划分为更易管理的单元，用来存放不同的程序对象（program object），即程序数据、指令和控制信息。这种划分完全是在虚拟地址空间中完成的。例如，C 语言中每个指针的值（无论它指向整数、结构体还是其他程序对象）都是某个存储块第一个字节的虚拟地址。C 编译器还会把每个指针与类型信息关联起来，以便根据指针值的类型生成不同的机器级代码，访问指针所指向位置存储的值。

    1.2 字长

    每台计算机都有一个字长（word size），指明指针数据的标称大小（nominal size）。由于虚拟地址是以一个字来编码的，对于字长为 位的机器，虚拟地址的取值范围为 ，程序最多可以访问 个字节。

    1.3 数据类型的大小

    图 2-3 展示了 C 语言各种数据类型分配的字节数：

    为了避免依赖“典型”大小以及不同编译器设置带来的奇怪行为，ISO C99 引入了一类数据大小固定、不随编译器和机器设置变化的数据类型，其中就包括 int32_t 和 int64_t，它们分别为 4 字节和 8 字节。使用确定大小的整数类型，是程序员精确控制数据表示的最佳途径。

    程序员应该尽量让程序在不同的机器和编译器上可移植，其中一个方面就是使程序对数据类型的确切大小不敏感。许多程序在编写时都假设了图 2-3 中 32 位程序的字节分配。随着 64 位机器日益普及，将这些程序移植到新机器时，许多隐藏的对字长的依赖就会显现出来，成为错误。比如，不少程序员假设 int 类型的程序对象足以存储一个指针，这在大多数 32 位机器上能正常工作，但在 64 位机器上却会导致问题。

    1.4 有符号数与无符号数

    大部分数据类型默认编码为有符号数值，除非带上前缀关键字 unsigned，或对确定大小的数据类型使用了特定的无符号声明。

    所谓“编码为有符号数值”，是指用二进制补码（two’s complement）等方式表示整数：最高有效位充当符号位，其余位表示数值大小，因此既能表示正数也能表示负数。与之相对，无符号编码把全部位都用于表示非负整数，取值范围更大。

    数据类型 char 是一个例外：尽管大多数编译器和机器把它视为有符号数，但 C 标准并不保证这一点。因此，如果需要保证一个字节的有符号数值，程序员应当使用 signed char 来显式声明。

    1.5 字节顺序：大端与小端

    在几乎所有的机器上，多字节对象 都被存储为连续的字节序列，对象的地址取所使用字节中最小的地址。表示一个对象字节的排列方式有两种通用规则：有些机器按从最低有效字节到最高有效字节的顺序存储对象，称为小端法（little endian）；另一些机器按从最高有效字节到最低有效字节的顺序存储，称为大端法（big endian）。

    2.4 C 语言中的位级运算

    C 语言的一个很有用的特性就是它支持按位布尔运算。事实上，我们在布尔运算中使用的那些符号也正是 C 语言所使用的：| 就是 OR（或），& 就是 AND（与），~ 就是 NOT（取反），^ 就是 EXCLUSIVE-OR（异或）。以下是一些对 char 类型数据表达式求值的例子：

    C 语言还提供了一组逻辑运算符 ||、&& 和 !，分别对应于命题逻辑中的 OR、AND 和 NOT 运算。逻辑运算很容易与位级运算相混淆，但二者的功能完全不同：逻辑运算把任何非零参数视为 TRUE、零视为 FALSE，并返回 1 或 0；此外，&& 和 || 还具有短路求值（short-circuit evaluation）的特性，一旦结果确定就停止对后续操作数的求值。

    2.5 掩码运算

    位级运算的一个常见用法就是实现掩码（mask）运算。掩码是一个位模式，表示从一个字中选出的位的集合。例如，掩码 0xFF（最低 8 位为 1）表示一个字中的低位字节：位级运算 x & 0xFF 生成一个由 x 的最低有效字节组成的值，而其他字节都被置为 0。比如，对于 x = 0x89ABCDEF，该表达式将得到 0x000000EF。

    ~0 会生成一个全 1 的掩码，与机器的字长无关。尽管对于 32 位机器来说，同样的掩码可以写成 0xFFFFFFFF，但这样的代码是不可移植的——在 64 位机器上它只覆盖低 32 位，无法得到全 1 的 64 位掩码。

    2.6 移位运算

    C 语言还提供了一组移位运算，向左或者向右移动位模式。对于操作数 x，C 表达式 x << k 会生成一个值，相当于把 x 向左移动 k 位，丢弃最高的 k 位，并在右端补 k 个 0。移位量应该是一个 之间的值，超出该范围的行为是未定义的（详见下面的提示）。移位运算是从左至右结合的，所以 x << j << k 等价于 (x << j) << k。

    移位量大于等于 时，C 标准规定其行为未定义。例如在 x86 上，移位量会被截断为低 5 位（32 位数据）或低 6 位（64 位数据），`x << 32` 实际等价于 `x << 0`；而在其他机器上可能表现不同。可移植代码应避免使用超出范围的移位量。

    有一个相应的右移运算 x >> k，但是它的行为有点微妙。一般而言，机器支持两种形式的右移：

    • 逻辑右移：在左端补 k 个 0；
    • 算术右移：在左端补 k 个最高有效位的值。

    算术右移的做法看上去可能有点奇特，但是我们会发现，它对有符号整数数据的运算非常有用。

    几乎所有的编译器/机器组合都对有符号数使用算术右移，且许多程序员也都假设机器会使用这种右移。另一方面，对于无符号数，右移必须是逻辑的。

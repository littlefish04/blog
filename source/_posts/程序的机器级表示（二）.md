## 一、条件码

到目前为止，我们只考虑了**直线**代码的行为，也就是指令一条接着一条顺序执行的情况。但 C 语言中的条件语句、循环语句和分支语句都要求**有条件地执行**——根据对数据测试的结果来决定操作的执行顺序。改变一组机器代码指令执行顺序的，正是跳转（jump）指令。

不过在介绍跳转指令之前，我们先来了解一个实现条件语句必不可少的东西：**条件码**。

### 1.1 条件码寄存器

除了整数寄存器，CPU 还维护着一组单个位的条件码（condition code）寄存器，它们描述了最近一次算术或逻辑操作的属性。我们可以检测这些寄存器，进而执行条件分支指令。最常用的条件码有四个，如下表所示：

| 标志 | 名称 | 置 1 的条件 |
| :--: | --- | --- |
| `CF` | 进位标志 | 最近的操作，如果是加法运算是否向最高有效位外产生进位，或在减法运算中是否发生借位。可用来检查无符号操作的溢出 |
| `ZF` | 零标志 | 最近的操作得出的结果为 0 |
| `SF` | 符号标志 | 最近的操作得到的结果为负数 |
| `OF` | 溢出标志 | 最近的操作导致一次补码溢出——正溢出或负溢出 |

#### 整数和逻辑指令如何设置条件码

举个例子：假设我们用一条 `ADD` 指令完成等价于 C 表达式 `t = a + b` 的功能，其中 `a`、`b` 和 `t` 都是整型。用 `t` 表示 ADD 指令得到的结果，则条件码按下面的规则设置（对应的 C 表达式为真时置 1，为假时置 0）：

| 条件码 | 置 1 的条件（C 表达式） | 含义 |
| :--: | --- | --- |
| `CF` | `(unsigned) t < (unsigned) a` | 无符号溢出 |
| `ZF` | `t == 0` | 结果为零 |
| `SF` | `t < 0` | 结果为负数 |
| `OF` | `(a < 0 == b < 0) && (t < 0 != a < 0)` | 有符号溢出 |

初次接触这张表，最容易困惑的是 `CF`：`a`、`b`、`t` 明明都是整型（机器里以补码存放），怎么会冒出一个「无符号溢出」？关键在于，**CPU 的加法器并不区分有符号与无符号**——它只是把 `a` 和 `b` 的位模式逐位相加，再把最高位产生的进位输出记录到 `CF` 中。不管是有符号数还是无符号数，计算机内部都是**使用补码进行运算**的，只是对结果位模式的解读不同。从无符号的视角看，如果两个 $w$ 位无符号数相加需要 $w+1$ 位才能表示，就说明最高位发生了进位（溢出）；此时低 $w$ 位的结果（也就是 `t` 的位模式）必然小于其中任意一个操作数，于是 `(unsigned) t < (unsigned) a` 恰好刻画了这一情形。即使 `a`、`b`、`t` 在 C 语言里声明为有符号的整型，位模式相加时最高位同样可能产生进位，`CF` 照样会被置 1——只是在这种语义下 `CF` 不再有意义，有符号加法真正要关心的是 `OF`。

看两个具体的例子（以 64 位加法为例）会更清楚：

- `t = -1 + 1`：位模式 `0xFF…FF` 与 `0x00…01` 相加，得到 `0x00…00`，同时最高位产生了进位，因此 `CF = 1`、`ZF = 1`；而 `-1 + 1` 并没有发生有符号溢出，所以 `OF = 0`。
- `t = 0x7FFF…FF + 1`：符号位从 0 翻转为 1，结果按有符号解读变成了负数，这正是典型的有符号溢出，因此 `OF = 1`；但最高位没有产生进位，所以 `CF = 0`。

`ZF` 和 `SF` 则直观得多：结果的位模式全为 0 时 `ZF = 1`；结果的符号位为 1（按有符号解读为负）时 `SF = 1`。

`leaq` 指令不改变任何条件码，因为它是专门用来进行地址计算的。除此之外，图 3-10 中列出的所有指令（也就是上一篇《程序的机器级表示（一）》第五节介绍的 x86-64 整数与逻辑操作）都会设置条件码，但各类指令置位的方式略有差异：

- 对于 `AND`、`OR`、`XOR` 这类**逻辑操作**，进位标志和溢出标志会被设置为 0。原因是逻辑运算按位独立地产生每一位结果，位与位之间不存在「进位」或「借位」的传递，更谈不上补码溢出，硬件自然把 `CF` 和 `OF` 清零；`SF`、`ZF` 仍照常反映结果的符号位是否为零和位模式是否全为零。
- 对于**移位操作**，进位标志被设置为最后一个被移出的位，而溢出标志设置为 0。被移出字边界的那个位，正是这次移位「丢出」字范围的信息，把它暂存在 `CF` 中可以在需要时派上用场；移位不存在「同号相加导致符号翻转」那种加性溢出，因此 `OF` 被清零。
- `INC` 和 `DEC` 指令会设置溢出标志和零标志，但**不会改变进位标志**。这两条指令最常见的用途是更新循环计数器或指针，而 `CF` 常被多精度（扩展精度）算术当作进位链的一部分——若计数器自增顺手把 `CF` 改掉，正在进行的进位传递就会被破坏，所以设计上特意保留了它。

#### CMP 和 TEST 指令

除了图 3-10 中的指令，还有两类指令**只设置条件码，不改变任何其他寄存器**，它们都有 8、16、32 和 64 位形式，如下表所示（对应原书图 3-13，其中 `S1`、`S2` 表示两个操作数）：

| 指令类 | 8/16/32/64 位形式 | 等价于 | 行为 |
| --- | --- | --- | --- |
| `CMP` | `cmpb` / `cmpw` / `cmpl` / `cmpq` | `SUB` | 比较：计算 `S2 - S1`（两个操作数之差），只设置条件码，不更新目的寄存器 |
| `TEST` | `testb` / `testw` / `testl` / `testq` | `AND` | 测试：计算 `S1 & S2`（按位与），只设置条件码，不更新目的寄存器 |

`CMP` 指令根据两个操作数之差来设置条件码。除了只设置条件码而不更新目的寄存器之外，`CMP` 与 `SUB` 的行为完全一致：`cmpq b, a` 和 `subq b, a` 一样，都计算 $a - b$。若两个操作数相等，零标志会被置 1；而其余标志则用来确定两个操作数之间的大小关系：

- **无符号比较**：$a < b$ 当且仅当 `CF = 1`（相减时最高位发生了借位，得到的结果会是一个比 $a$ 大的无符号数）；$a = b$ 当且仅当 `ZF = 1`；$a > b$ 当且仅当 `CF = 0` 且 `ZF = 0`。
- **有符号比较**：$a < b$ 当且仅当 `SF ≠ OF`；$a = b$ 当且仅当 `ZF = 1`；$a > b$ 当且仅当 `SF = OF` 且 `ZF = 0`。

> 有符号比较为什么要同时考察 `SF` 和 `OF`？因为当 $a - b$ 发生有符号溢出时，结果的符号位会被「翻转」，只看 `SF` 会得到与事实相反的结论；`SF` 与 `OF` 不一致（异或为 1）恰好排除了溢出的干扰。这一规则在 1.2 节 SET 指令的表格中会体现得更直观。

`TEST` 指令的行为与 `AND` 指令一样，区别只在于它不改变目的寄存器的值，仅设置条件码（`CF` 与 `OF` 恒为 0）。它的典型用法有两种：

- **两个操作数相同**：`testq %rax, %rax` 相当于让 `%rax` 与自己相与，结果就是 `%rax` 本身。于是 `ZF = 1` 表示 `%rax` 为 0，`SF = 1` 表示 `%rax` 为负数，`SF = 0` 且 `ZF = 0` 表示 `%rax` 为正数——这正是用 `testq %rax, %rax` 检查 `%rax` 是负数、零还是正数的原理。
- **一个操作数是掩码（mask）**：掩码中为 1 的那些位，会把另一个操作数对应位置上的位「过滤」出来，从而只测试感兴趣的位。例如 `testq $1, %rax` 只保留最低位：`ZF = 1` 说明最低位为 0（`%rax` 为偶数），否则最低位为 1（`%rax` 为奇数）；`testb $0x80, %al` 则可用来检查 `%al` 的最高位（符号位）。

### 1.2 访问条件码

条件码通常不会被直接读取，使用它们的方式主要有三种：

1. 根据条件码的某种组合，将一个字节设置为 0 或 1；
2. 条件跳转到程序的某个其他部分；
3. 有条件地传送数据。

本节先介绍第一种情况（SET 指令），第二、三种分别对应之后会讲到的的跳转指令，以及条件传送指令。

#### SET 指令

对于第一种情况，下表中的指令会根据条件码的某种组合，把一个字节设置为 0 或 1（`0x00` 或 `0x01`）。我们把这整类指令统称为 SET 指令；它们之间的区别只在于所考察的条件码组合不同，指令名中不同的后缀正指明了这种组合（注意这里的后缀不表示操作数的大小）。

| 指令 | 同义名 | 置 1 的条件 | 表示的情况 |
| --- | --- | --- | --- |
| `sete D` | `setz` | `ZF` | 相等 / 为零 |
| `setne D` | `setnz` | `~ZF` | 不相等 / 不为零 |
| `sets D` |  | `SF` | 为负数 |
| `setns D` |  | `~SF` | 为非负数 |
| `setg D` | `setnle` | `~(SF^OF) & ~ZF` | 大于（有符号 >） |
| `setge D` | `setnl` | `~(SF^OF)` | 大于等于（有符号 >=） |
| `setl D` | `setnge` | `SF^OF` | 小于（有符号 <） |
| `setle D` | `setng` | `(SF^OF) | ZF` | 小于等于（有符号 <=） |
| `seta D` | `setnbe` | `~CF & ~ZF` | 大于（无符号 >） |
| `setae D` | `setnb` | `~CF` | 大于等于（无符号 >=） |
| `setb D` | `setnae` | `CF` | 小于（无符号 <） |
| `setbe D` | `setna` | `CF | ZF` | 小于等于（无符号 <=） |

表中 `D` 表示目的操作数；`~` 为逻辑取反（如 `~ZF` 表示「ZF 为 0」），`^` 为异或。对照 1.1 节 CMP 的结论可以看到：无符号比较（`seta`、`setb` 一族）只依赖 `CF` 和 `ZF`，有符号比较（`setg`、`setl` 一族）则依赖 `SF`、`OF` 和 `ZF`，两者并不通用。

一条 SET 指令的目的操作数必须是低位单字节寄存器（如 `%al`），或是一个字节的内存位置，指令会将这个字节设置为 0 或 1。

#### 比较的典型指令序列

一个计算 C 语言表达式 `a < b` 的典型指令序列如下所示，这里 `a` 和 `b` 都是 `long` 类型：

```asm
# a in %rdi, b in %rsi
cmpq    %rsi, %rdi   # 比较 a 与 b，即计算 a - b
setl    %al          # 若 a < b（有符号），把 %al 置为 1，否则置为 0
movzbl  %al, %eax    # 把 %al 零扩展写入 %eax
```

`setl` 判断的是有符号的「小于」（条件为 `SF^OF = 1`），因此上面这段代码计算的是有符号比较 `a < b`；若要比较无符号大小，把 `setl` 换成 `setb` 即可。另外要记得，正如前面讨论过的那样，`movzbl` 指令不仅会把 `%eax` 的高 3 个字节清零，还会把整个寄存器 `%rax` 的高 4 个字节都清零——任何以 32 位寄存器为目的的操作，都会隐式地把 64 位寄存器的高 32 位清零。

从上面的表格还可以看到，有些底层的机器指令可能有多个名字，我们称之为「同义名」（synonym）。比如说，`setg`（表示「设置大于」）和 `setnle`（表示「设置不小于等于」）指的就是同一条机器指令。编译器和反汇编器会随意决定使用哪个名字，两种写法效果完全相同。

#### 机器代码中的有符号和无符号值

注意到机器代码如何区分有符号和无符号值是很重要的。同 C 语言不同，机器代码不会把每个程序值都与某个数据类型联系起来；大多数情况下，它对有符号和无符号两种情况使用一样的指令，这是因为许多算术运算对无符号和补码算术具有相同的位级行为。但在少数情况下，机器代码必须用不同的指令（或不同的条件码组合）来处理有符号和无符号操作。

把《程序的机器级表示（一）》和本文讲过的指令汇总起来，可以整理成下面这份清单：

**位级行为一致、可共用同一指令的情况：**

- **加减法**（`ADD`/`SUB`）与一元操作（`INC`/`DEC`/`NEG`）：补码加法与无符号加法在模 $2^w$ 下本就是同一种位级运算；
- **逻辑操作**（`AND`/`OR`/`XOR`/`NOT`）：按位运算与符号无关；
- **左移**（`SAL`/`SHL`）：一律低位补 0，位级行为一致；
- **双操作数乘法** `imulq`：乘积截断到 $w$ 位后，无符号乘法与补码乘法的位级结果相同；
- **数据传送** `mov*` 与地址计算 `leaq`：只是搬运位模式，不做算术解释；
- **`CMP`/`TEST` 指令本身**：也只有一条，差别体现在之后如何解读 `CF`/`ZF`/`SF`/`OF`（选择不同的 SET 或跳转条件）。

**必须区分、使用不同指令或不同条件的情况：**

| 场景 | 有符号 | 无符号 |
| --- | --- | --- |
| 右移 | `SAR`（算术右移，高位补符号位） | `SHR`（逻辑右移，高位补 0） |
| 全 128 位乘法 | `imulq` | `mulq` |
| 除法及被除数准备 | `idivq` + `cqto`（把 `%rax` 符号扩展到 `%rdx`） | `divq`（`%rdx` 清零） |
| 大小比较后的置位 | `setg`/`setge`/`setl`/`setle`（考察 `SF`/`OF`/`ZF`） | `seta`/`setae`/`setb`/`setbe`（考察 `CF`/`ZF`） |
| 零扩展与符号扩展 | `MOVS` 族（如 `movslq`、`cltq`） | `MOVZ` 族（如 `movzbl`） |

之所以多数运算能「一套指令通吃」，根源在于补码的设计：补码数的加减法与逻辑运算在位的层面与无符号数完全一致，只有那些需要解释最高位（符号位）语义的操作——右移时高位补什么、乘除结果如何解读、大小关系如何判定——才必须区分有符号与无符号。

## 二、跳转指令

正常情况下，指令按照它们在代码中出现的顺序一条一条地执行。**跳转（jump）指令**则会让执行切换到程序中一个全新的位置，从而实现「有条件地执行」。在汇编代码中，跳转的目的地通常用一个**标号（label）**来指明。考虑下面的汇编代码序列（完全是人为编造的）：

```asm
movq $0, %rax       # 将 %rax 置为 0
jmp  .L1            # 跳转到标号 .L1
movq (%rax), %rdx   # 空指针解引用（被跳过）
.L1:
popq %rdx           # 跳转目标
```

`jmp .L1` 会让程序跳过中间的 `movq` 指令，直接从 `popq` 指令开始继续执行。在生成目标代码文件时，汇编器会确定所有带标号指令的地址，并将跳转目标（目的指令的地址）编码为跳转指令的一部分。

> 这里的「确定地址」发生在汇编阶段：汇编器为每条指令分配地址（从 0 开始计数），凡是出现标号的地方，都能在这一步算出它所标记的那条指令的地址。同一文件内部的跳转目标因此可以在汇编时直接编码；而跨模块的符号（例如调用其他文件中定义的函数）则要等到链接阶段、布局确定后才能解析。

### 2.1 JMP 指令和有条件跳转

下表（对应原书图 3-15）列举了不同的跳转指令：

| 指令 | 同义名 | 跳转条件 | 说明 |
| --- | --- | --- | --- |
| `jmp Label` |  | 1 | 直接跳转 |
| `jmp *Operand` |  | 1 | 间接跳转 |
| `je Label` | `jz` | `ZF` | 相等 / 为零 |
| `jne Label` | `jnz` | `~ZF` | 不相等 / 不为零 |
| `js Label` |  | `SF` | 为负数 |
| `jns Label` |  | `~SF` | 为非负数 |
| `jg Label` | `jnle` | `~(SF^OF) & ~ZF` | 大于（有符号 >） |
| `jge Label` | `jnl` | `~(SF^OF)` | 大于等于（有符号 >=） |
| `jl Label` | `jnge` | `SF^OF` | 小于（有符号 <） |
| `jle Label` | `jng` | `(SF^OF) \| ZF` | 小于等于（有符号 <=） |
| `ja Label` | `jnbe` | `~CF & ~ZF` | 大于（无符号 >） |
| `jae Label` | `jnb` | `~CF` | 大于等于（无符号 >=） |
| `jb Label` | `jnae` | `CF` | 小于（无符号 <） |
| `jbe Label` | `jna` | `CF \| ZF` | 小于等于（无符号 <=） |

`jmp` 指令是无条件跳转，它可以是**直接**跳转，即跳转目标是作为指令的一部分编码的；也可以是**间接**跳转，即跳转目标是从寄存器或内存位置中读出的。在汇编语言中，直接跳转直接给出一个标号作为跳转目标，例如上文代码中的标号 `.L1`；间接跳转的写法是在操作数前加一个 `*`，操作数可以是寄存器或任意一种内存操作数格式，例如 `(%rax)`、`8(%rax,%rcx,4)` 等。

举个例子，指令

```asm
jmp *%rax
```

用寄存器 `%rax` 中的值作为跳转目标；而指令

```asm
jmp *(%rax)
```

则是以 `%rax` 中的值作为读地址，从内存中读出跳转目标。这两种间接跳转的语义都很直接：跳转目标本质上就是一条指令的地址，`jmp *%rax` 相当于「跳到 `%rax` 内保存的地址」，`jmp *(%rax)` 则是「先到 `%rax` 指向的内存单元取地址，再跳到该地址」。

上表其余跳转指令都是**有条件的**——它们根据条件码的某种组合，决定是跳转，还是继续执行代码序列中的下一条指令。这些指令的名字和跳转条件与 SET 指令完全对应（可回看 1.2 节的表格），例如 `setl` 考察 `SF^OF`，`jl` 也考察 `SF^OF`。与 SET 指令类似，一些底层机器指令存在多个名字（同义名），编译器和反汇编器会随意选用其一，两种写法效果完全相同。另外需要注意的是：**条件跳转只能是直接跳转**。

### 2.2 跳转指令的编码

虽然我们通常不必关心二进制机器代码格式的细节，但理解跳转指令的目标是如何编码的，对第 7 章研究链接非常重要，也能帮助我们看懂反汇编器的输出。

在汇编代码中，跳转目标用符号标号书写。汇编器（以及随后的链接器）会为跳转目标产生适当的二进制编码。跳转指令主要有两种编码方式：

- **PC 相对的（PC-relative）**：最常用。编码内容是「目标指令的地址与程序计数器的值之差」。后文会看到，这里的程序计数器值取的是跳转指令**后面那条指令**的地址，而不是跳转指令本身的地址。这类地址偏移量可以编码为 1、2 或 4 个字节。
- **绝对地址**：用 4 个字节直接指定目标。

具体采用哪种编码，由汇编器和链接器根据情况选择。

#### PC 相对寻址的例子

下面是一个 PC 相对寻址的例子。考虑下面这段汇编代码（由某个 C 函数编译而来，函数符号名为 `loop`），它包含两个跳转：第 2 行的 `jmp` 指令前向跳转到更高的地址，而第 7 行的 `jg` 指令后向跳转到较低的地址：

```asm
movq    %rdi, %rax
jmp     .L2
.L3:
sarq    %rax
.L2:
testq   %rax, %rax
jg      .L3
rep; ret
```

汇编器产生的 `.o` 格式的反汇编版本如下：

```asm
0:  48 89 f8    mov    %rdi,%rax
3:  eb 03       jmp    8 <loop+0x8>
5:  48 d1 f8    sar    %rax
8:  48 85 c0    test   %rax,%rax
b:  7f f8       jg     5 <loop+0x5>
d:  f3 c3       repz   retq
```

反汇编器在右侧注释中给出跳转目标：第 2 行跳转指令的目标是 `0x8`，第 5 行跳转指令的目标是 `0x5`（反汇编器一律以十六进制格式给出数字）。观察指令的二进制字节编码，会看到第一条跳转指令的目标编码（位于第二个字节）为 `0x03`：把它加上 `0x5`——也就是下一条指令（`sarq`）的地址——就得到跳转目标地址 `0x8`，即 `testq` 那条指令的地址。

类似地，第二条跳转指令的目标用单字节补码编码为 `0xf8`（十进制 -8）。把这个数加上 `0xd`（十进制 13，即 `repz retq` 的地址），得到 `0x5`，也就是 `sarq` 指令的地址。

这些例子说明：当执行 PC 相对寻址时，程序计数器的值是**跳转指令后面那条指令**的地址，而不是跳转指令本身的地址。这种惯例可以追溯到早期的实现——当时的处理器把「更新程序计数器」作为执行一条指令的第一步。

下面是链接后的程序反汇编版本：

```asm
4004d0:  48 89 f8    mov    %rdi,%rax
4004d3:  eb 03       jmp    4004d8 <loop+0x8>
4004d5:  48 d1 f8    sar    %rax
4004d8:  48 85 c0    test   %rax,%rax
4004db:  7f f8       jg     4004d5 <loop+0x5>
4004dd:  f3 c3       repz   retq
```

链接后这些指令被重定位到不同的地址，但第 2 行和第 5 行中跳转目标的编码（`eb 03`、`7f f8`）并没有改变。使用 PC 相对的跳转目标编码有两大好处：指令编码很简洁（两条跳转都只需要 2 个字节）；目标代码可以不做任何修改就搬到内存中不同的位置。

> **旁注：指令 `rep` 和 `repz` 有什么用**
>
> 本节开头的汇编代码第 8 行包含指令组合 `rep; ret`，它在反汇编代码（第 6 行）中对应 `repz retq`。可以推测 `repz` 是 `rep` 的同义名，而 `retq` 是 `ret` 的同义名。查阅 Intel 和 AMD 关于 `rep` 的文档会发现，它通常用来实现重复的字符串操作，用在这里似乎很不合适。这个问题的答案藏在 AMD 给编译器编写者的指导意见中：他们建议用 `rep` 后跟 `ret` 的组合，来避免使 `ret` 指令成为条件跳转指令的目标。如果没有 `rep`，当分支不跳转时，`jg` 指令（汇编代码的第 7 行）会继续执行到 `ret` 指令；而根据 AMD 的说法，当 `ret` 指令是通过跳转指令到达时，处理器不能正确预测 `ret` 指令的目的。这里的 `rep` 就是一条空操作，把它作为跳转目标插入，除了能让代码在 AMD 处理器上运行得更快之外，不会改变代码的其他行为。在本书后面的代码中再遇到 `rep` 或 `repz`，我们可以放心地无视它们。

### 2.3 用跳转实现条件分支

将条件表达式和语句从 C 语言翻译成机器代码，最常用的方式是结合有条件和无条件跳转。

#### 示例代码

例如，下面的 C 代码（对应原书图 3-16a）是一个计算两数之差绝对值的函数。这个函数有一个副作用：它会增加两个计数器，具体加哪个由比较结果决定，两个计数器编码为全局变量 `lt_cnt` 和 `ge_cnt`：

```c
long lt_cnt = 0;
long ge_cnt = 0;

long absdiff_se(long x, long y)
{
    long result;
    if (x < y) {
        lt_cnt++;
        result = y - x;
    } else {
        ge_cnt++;
        result = x - y;
    }
    return result;
}
```

把这个 C 代码翻译成机器代码再转回 C 语言，可以得到下面的 `gotodiff_se`（对应原书图 3-16b）。它使用了 C 语言的 `goto` 语句——该语句类似于汇编代码中的无条件跳转。虽然使用 `goto` 通常被认为是不好的编程风格（会让代码难以阅读和调试），但本文用它是为了构造出与汇编代码控制流一一对应的 C 程序，我们称这种风格为「goto 代码」：

```c
long gotodiff_se(long x, long y)
{
    long result;
    if (x >= y)
        goto x_ge_y;
    lt_cnt++;
    result = y - x;
    return result;
x_ge_y:
    ge_cnt++;
    result = x - y;
    return result;
}
```

GCC 为 `absdiff_se` 生成的汇编代码（对应原书图 3-16c）如下。它首先用 `cmpq` 比较两个操作数并设置条件码；如果结果表明 `x >= y`，`jge` 就会跳到 `.L2` 分支——在那里 `ge_cnt++`、计算 `x - y` 作为返回值并返回；否则落入上一分支，执行 `lt_cnt++`、计算 `y - x`：

```asm
# x in %rdi, y in %rsi
absdiff_se:
    cmpq    %rsi, %rdi          # 比较 x 与 y
    jge     .L2                 # 若 x >= y，跳转到 .L2
    addq    $1, lt_cnt(%rip)    # lt_cnt++
    subq    %rdi, %rsi          # result = y - x
    movq    %rsi, %rax
    ret
.L2:
    addq    $1, ge_cnt(%rip)    # ge_cnt++
    subq    %rsi, %rdi          # result = x - y
    movq    %rdi, %rax
    ret
```

> 关于 `addq $1, lt_cnt(%rip)` 这行：`lt_cnt` 是定义在 C 源文件里的全局变量，汇编器无法预知它最终会被链接到哪个地址，因此这里采用的是 **RIP 相对寻址**——把目标地址写成「下一条指令的地址（`%rip`）+ 一个由链接器填充的偏移量」。CPU 执行这条指令时，`%rip` 已指向下一条指令，用 `%rip` 加上指令中编码的偏移量，就能算出 `lt_cnt` 在内存中的真实地址，再把 1 加到该内存单元上，从而完成 `lt_cnt++`。这也正是全局变量在位置无关代码（PIC）中的典型访问方式。

对比 `absdiff_se` 的汇编与 `gotodiff_se` 的 goto 代码可以看到，两者的控制流高度一致：`if (x >= y) goto x_ge_y;` 对应 `jge .L2`，`lt_cnt++; result = y - x; return result;` 对应中间那几条指令，`x_ge_y:` 标签之后的代码则对应 `.L2` 分支。

#### 通用模板

C 语言中 `if-else` 语句的通用形式如下：

```c
if (test-expr)
    then-statement
else
    else-statement
```

其中 `test-expr` 是一个整数表达式，取值为 0（解释为「假」）或非 0（解释为「真」），两个分支语句（`then-statement` 或 `else-statement`）只会执行其中一个。

对这种通用形式，汇编实现通常会采用下面的结构。这里我们用 C 语法来描述控制流：

```c
    t = test-expr;
    if (!t)
        goto false;
    then-statement
    goto done;
false:
    else-statement
done:
```

也就是说，汇编器会为 `then-statement` 和 `else-statement` 各生成一块代码，再插入条件分支与无条件分支，以保证最终只执行正确的代码块：`test-expr` 为真就落入 `then` 块，执行完用无条件跳转越过 `else` 块；为假则 `goto false` 直接进入 `else` 块。

#### 练习题

已知下列 C 代码：

```c
void cond(long a, long *p)
{
    if (p && a > *p)
        *p = a;
}
```

GCC 会产生下面的汇编代码：

```asm
# a in %rdi, p in %rsi
cond:
    testq   %rsi, %rsi      # p 是否为 NULL？
    je      .L1             # 若 p == NULL，跳过赋值
    cmpq    %rdi, (%rsi)    # 比较 a 与 *p
    jge     .L1             # 若 a <= *p，跳过赋值
    movq    %rdi, (%rsi)    # *p = a
.L1:
    rep; ret
```

**请说明：为什么 C 语言代码中只有一个 `if` 语句，而汇编代码包含两个条件分支？**

答案：第一个条件分支（`je`）是 `&&` 表达式实现的一部分。如果对 `p` 为非空的测试失败（`p == NULL`），代码会跳过对 `a > *p` 的测试——这正是 `&&` 的短路特性：一旦左侧为假，右侧根本不会被求值，自然也就不会去解引用 `p`。第二个条件分支（`jge`）才是对 `a > *p` 本身的判断。两者都跳到 `.L1` 跳过赋值，保证只有 `p != NULL && a > *p` 成立时才执行 `*p = a`。

## 三、条件传送指令

实现条件操作的传统方法，是通过**基于控制的条件转移**：当条件满足时，程序沿着一条执行路径走下去，条件不满足时则走另一条路径。这种机制简单而通用，但在现代处理器上，它可能会非常低效（原因见 3.2 节）。

另一种替代策略是**基于数据的条件转移**：把条件操作的两种结果都计算出来，再根据条件是否满足从中选取一个。这种策略只在一些受限制的情况下才可行——比如两条路径都必须没有副作用（不能修改内存或计数变量），而且都能安全执行（例如不能出现空指针解引用这类可能出错的操作）。不过只要可行，就能用一条简单的**条件传送指令**（conditional move）来实现，它更符合现代处理器的性能特性。

### 3.1 示例代码

下面的 C 代码（对应原书图 3-17a）给出了一个可以用条件传送来编译的示例。这个函数计算参数 `x` 和 `y` 之差的绝对值，和 2.3 节中的 `absdiff_se` 一样；不过 `absdiff_se` 的分支里有副作用（会修改 `lt_cnt` 或 `ge_cnt` 的值），而这个版本只是单纯地计算函数要返回的值：

```c
long absdiff(long x, long y)
{
    long result;
    if (x < y)
        result = y - x;
    else
        result = x - y;
    return result;
}
```

GCC 为该函数生成的汇编代码（对应原书图 3-17c）与图 3-17b 中手写的 C 函数 `cmovdiff` 有相似的形式。我们先看这个 C 版本：它既计算了 `y - x`，也计算了 `x - y`，分别命名为 `rval` 和 `eval`；随后测试 `x` 是否大于等于 `y`，如果是，就在函数返回 `rval` 之前把 `eval` 复制到 `rval` 中：

```c
long cmovdiff(long x, long y)
{
    long rval = y - x;
    long eval = x - y;
    long ntest = x >= y;
    /* 下一行应该编译成一条指令 */
    if (ntest)
        rval = eval;
    return rval;
}
```

再看图 3-17c 的汇编代码，它的逻辑与 `cmovdiff` 完全相同。关键就在于其中的 `cmovge` 指令——它实现了 `cmovdiff` 里的那个条件赋值：只有当 `cmpq` 指令的比较结果表明一个值大于等于另一个值（正如后缀 `ge` 表明的那样）时，才把数据源寄存器传送到目的寄存器：

```asm
# x in %rdi, y in %rsi
absdiff:
    movq    %rsi, %rax      # 计算 y - x，即 rval
    subq    %rdi, %rax
    movq    %rdi, %rdx      # 计算 x - y，即 eval
    subq    %rsi, %rdx
    cmpq    %rsi, %rdi      # 比较 x 与 y，设置条件码
    cmovge  %rdx, %rax      # 若 x >= y，将 eval 复制到 rval（%rax）
    ret
```

对照着看就能发现对应关系：`rval` 放在 `%rax`、`eval` 放在 `%rdx`，`cmpq` 完成 `ntest = x >= y` 的求值，而 `cmovge %rdx, %rax` 正是 `if (ntest) rval = eval;` 的机器级实现——条件不满足时它什么都不做，`%rax` 保持 `y - x` 不变；条件满足时则把 `x - y` 送进 `%rax`。无论走哪条路径，最终 `%rax` 里都是差的绝对值。

### 3.2 为什么条件数据传送性能更好

要理解为什么基于条件数据传送的代码（如 3.1 节的 `absdiff`）会比基于条件控制转移的代码（如 2.3 节的 `absdiff_se`）更快，先要了解现代处理器是如何运行的。正如第 4、5 章将要讲到的，处理器通过**流水线（pipelining）**获得高性能：一条指令的处理被拆成一系列阶段，每个阶段只完成一小部分工作——取指令、确定指令类型、读数据、执行算术运算、写回数据、更新程序计数器。相邻指令的阶段可以重叠进行，例如在取一条指令的同时，执行它前面那条指令的算术运算。这样一来，只要流水线保持「充满」待执行指令，处理器就能持续高速运转。

流水线高效运转的前提，是**能提前确定接下来要执行的指令序列**。条件跳转（也称「分支」）恰恰破坏了这一点：分支条件求值完成之前，无法判断执行流往哪边走。处理器为此引入了精密的分支预测逻辑，猜测每条跳转指令是否会被执行。只要猜得足够准（现代微处理器设计的成功率在 90% 以上），流水线就能保持充满；可一旦**预测错误**，处理器必须丢弃为分支之后所有指令已做的工作，再从头用正确位置处的指令填充流水线。一次错误预测会招致很严重的惩罚，浪费大约 $15\sim30$ 个时钟周期，使程序性能严重下降。

条件传送则完全绕开了这个问题：它把两条路径的结果都算好，用一条 `cmov` 指令按条件选取，**根本不产生分支**，也就没有「猜错」的可能。控制流不依赖数据，处理器始终能保持流水线充满。

原书在 Intel Haswell 处理器上实测了 `absdiff` 函数的两种实现，结论很直观：两个版本里的计算都只花约 1 个时钟周期，性能差距几乎全部来自分支预测惩罚。对于带条件跳转的版本，当分支行为模式很容易预测时，每次调用约需 8 个时钟周期；当分支模式随机（例如典型的应用中 `x < y` 几乎不可预测，预测硬件只有约 50% 的正确率）时，每次调用约需 17.50 个时钟周期——据此可推断一次分支预测错误的惩罚约为 19 个时钟周期，函数耗时在 8 到 27 个周期之间波动。而使用条件传送的版本，无论测试数据如何，每次调用都稳定在约 8 个时钟周期。

### 3.3 CMOV 指令

下表（对应原书图 3-18）列举了 x86-64 上一些可用的条件传送指令。每条指令都有两个操作数：源操作数 `S`（可以是寄存器或内存地址）和目的寄存器 `R`。与 `SET`（见 1.2 节）和跳转指令（见 2.1 节）类似，这些指令的执行效果同样取决于条件码的值：源值既可以从内存读取，也可以从源寄存器读取，但只有当指定的条件成立时，才会被复制到目的寄存器中。

| `cmov` 指令 | 同义名 | 传送条件 | 描述 |
|------------|--------|----------|------|
| `cmove S, D` | `cmovz` | `ZF` | 相等 / 为零 |
| `cmovne S, D` | `cmovnz` | `~ZF` | 不相等 / 不为零 |
| `cmovs S, D` | — | `SF` | 负数 |
| `cmovns S, D` | — | `~SF` | 非负数 |
| `cmovg S, D` | `cmovnle` | `~(SF^OF) & ~ZF` | 大于（有符号 >） |
| `cmovge S, D` | `cmovnl` | `~(SF^OF)` | 大于等于（有符号 >=） |
| `cmovl S, D` | `cmovnge` | `SF^OF` | 小于（有符号 <） |
| `cmovle S, D` | `cmovng` | `(SF^OF) \| ZF` | 小于等于（有符号 <=） |
| `cmova S, D` | `cmovnbe` | `~CF & ~ZF` | 大于（无符号 >） |
| `cmovae S, D` | `cmovnb` | `~CF` | 大于等于（无符号 >=） |
| `cmovb S, D` | `cmovnae` | `CF` | 小于（无符号 <） |
| `cmovbe S, D` | `cmovna` | `CF \| ZF` | 小于等于（无符号 <=） |

表中 `S` 为源操作数、`D` 为目的寄存器。可以看到，条件传送指令的命名与传送条件和前面的 `set`、`jmp` 一族完全对应——无符号比较只依赖 `CF` 与 `ZF`，有符号比较依赖 `SF`、`OF` 与 `ZF`。

条件传送指令的源与目的可以是 16 位、32 位或 64 位长，但不支持单字节（8 位）的条件传送。由于汇编器可以从目标寄存器的名字推断出操作数的长度，因此对所有长度的操作数，都可以沿用同一条指令助记符。

与条件跳转不同，处理器无需预测测试的结果就能执行条件传送。它只是读取源值（可能来自内存），检查条件码，然后决定是更新目的寄存器，还是让它保持不变。

#### 条件控制转移和条件传送的对比

考虑下面的条件表达式及赋值的通用形式：

```c
v = test-expr ? then-expr : else-expr;
```

用条件控制转移的标准方法编译这个表达式，会得到如下所示的形式：

```c
    t = test-expr;
    if (!t)
        goto false;
    v = then-expr;
    goto done;
false:
    v = else-expr;
done:
```

这段代码包含两个代码序列：一个对 `then-expr` 求值，另一个对 `else-expr` 求值；通过组合使用条件跳转与无条件跳转，保证最终只有其中一个序列会被执行。

而基于条件传送的实现，则会对 `then-expr` 和 `else-expr` 都求值，最终值的选择取决于对 `test-expr` 的求值结果。可以用下面的抽象代码来描述：

```c
v  = then-expr;
ve = else-expr;
t  = test-expr;
if (!t)
    v = ve;
```

在这个序列中，最后一条语句正是用条件传送实现的——只有当测试条件 `t` 不成立时，`ve` 的值才会被复制到 `v` 中。

#### 条件传送指令的限制

无论测试结果如何，上面的抽象代码都会对 `then-expr` 与 `else-expr` 都求值；如果其中任何一个表达式可能产生错误条件或副作用，就会导致非法的行为。此前的 `absdiff_se` 函数就属于这种情况——事实上，我们当初正是通过在示例中**引入**副作用，才强制 GCC 用条件转移而非条件传送来编译这个函数。

作为说明，考虑下面这个 C 函数：

```c
long cread(long *xp)
{
    return xp ? *xp : 0;
}
```

乍一看，这段代码似乎很适合被编译成使用条件传送——当指针为空时将结果设置为 0。其汇编代码可能如下所示：

```asm
# xp in %rdi
cread:
    movq	(%rdi), %rax	   # v = *xp（无条件解引用！）
    testq   %rdi, %rdi         # 测试 xp 是否为空
	movl	$0, %edx		   # ve = 0
    cmovne  %rdx, %rax         # 若 xp 非空，取 *xp；否则保持 0
    ret
```

不过，这样的实现是非法的：即使测试条件为假，示例中的 `movq` 指令仍会对 `xp` 进行间接引用，从而触发空指针解引用的错误。因此，这段代码必须改用条件分支来编译。

使用条件传送也并非总能提高代码效率。例如，如果 `then-expr` 或 `else-expr` 的求值需要大量的计算，那么当对应条件不成立时，这些计算就白费了。编译器必须在「被浪费的计算」与「分支预测错误造成的性能处罚」之间权衡。说实话，编译器往往缺少足够的信息来做出可靠的决定——例如，它们并不知道某个分支会在多大程度上遵循可预测的模式。我们对 GCC 的实测表明：只有当两个表达式都很容易计算（比如各自只对应一条加法指令）时，它才会采用条件传送；而根据经验，即使不少分支预测错误的开销超过了更复杂的计算，GCC 多数情况下仍会选择条件控制转移。

## 四、循环的实现

C 语言提供了多种循环结构：`do-while`、`while` 和 `for`。汇编语言中并没有专门的循环指令，而是用条件测试与跳转指令组合起来实现循环的效果。我们会循序渐进地研究循环的翻译方式：先从 `do-while` 开始，再研究实现起来更复杂的循环。

### 4.1 do-while 循环

do-while 语句的通用形式如下：

```c
do
    body-statement
    while(test-expr);
```

这个循环的效果是反复执行 `body-statement`，每次都对 `test-expr` 求值；只要求值结果为非零，就继续循环。可以看到，`body-statement` 至少会被执行一次。

这种通用形式可以被翻译成下面这种使用条件与 `goto` 语句表达的版本：

```c
loop:
    body-statement
    t = test-expr;
    if (t)
        goto loop;
```

也就是说，每次循环程序都会先执行循环体里的语句，再执行测试表达式；如果测试为真，就跳回循环开始处再执行一次。

#### 示例

看一个示例：图 3-19a（即下方所示）给出了一个用 `do-while` 循环计算参数阶乘（记作 `n!`）的函数。该函数只计算 `n > 0` 时 `n!` 的值，无法正确算出 `0! = 1`。

图 3-19b 所示的 `goto` 代码展示了如何把循环改写成低级的「测试 + 条件跳转」组合：`result` 初始化之后程序进入循环，先执行循环体（更新变量 `result` 和 `n`），再测试 `n > 1`；若为真，就跳回循环开始处。图 3-19c 所示的汇编代码正是这段 `goto` 代码的原型，其中条件跳转指令 `jg` 是实现循环的关键指令——它决定了是继续重复循环，还是退出循环。

**（a）用 `do-while` 写的 C 函数 `fact_do`：**

```c
long fact_do(long n)
{
    long result = 1;
    do {
        result *= n;
        n = n - 1;
    } while (n > 1);
    return result;
}
```

**（b）等价的 `goto` 代码：**

```c
long fact_do(long n)
{
    long result = 1;
loop:
    result *= n;
    n = n - 1;
    if (n > 1)
        goto loop;
    return result;
}
```

**（c）GCC（`-Og`）生成的汇编代码：**

```asm
# n in %rdi
fact_do:
    movl    $1, %eax            # result = 1
.L2:                            # loop:
    imulq   %rdi, %rax          # result *= n
    subq    $1, %rdi            # n = n - 1
    cmpq    $1, %rdi            # n 与 1 比较
    jg      .L2                 # 若 n > 1，跳回 loop
    rep; ret
```

### 4.2 while 循环

while 语句的通用形式如下：

```c
while (test-expr)
    body-statement;
```

与 `do-while` 不同，`while` 会在第一次执行 `body-statement` 之前就对 `test-expr` 求值，因此循环体有可能一次都不会执行。将 `while` 循环翻译成机器代码有多种方法，GCC 在代码生成时会使用其中两种。这两种方法采用与 `do-while` 相同的循环结构，区别只在于它们实现**初始测试**的方式不同。

#### 跳转到中间

第一种翻译方法称为**跳转到中间**（jump to middle）：先执行一个无条件跳转，跳到位于循环结尾处的测试，借此完成初始测试。下面这个模板表达的就是这种方法——它把通用的 `while` 循环格式翻译成 `goto` 代码：

```c
    goto test;
loop:
    body-statement
test:
    t = test-expr;
    if (t)
        goto loop;
```

作为示例，下方代码（对应图 3-20a） 给出使用 `while` 循环的阶乘函数实现，它能够正确计算 `0! = 1`。它旁边的函数 `fact_while_jm_goto`（图 3-20b）是 GCC 在优化命令行选项 `-Og` 下产生的汇编代码的 C 语言翻译。对比 `fact_while_jm_goto`（图 3-20b）与 `fact_do` 的 goto 代码（图 3-19b）可以发现，两者的代码非常相似，区别仅在于：`fact_while_jm_goto` 在循环前多了一条 `goto test` 语句，使得程序在修改 `result` 或 `n` 的值之前，先执行对 `n` 的测试。

图的最下面（图 3-20c）给出的是实际生成的汇编代码。可以看到编译器采用的正是跳转到中间的翻译方法：先在第 4 行用 `jmp` 跳转到以标号 `.L2` 开头的测试部分。

**（a）用 `while` 写的 C 函数 `fact_while`：**

```c
long fact_while(long n)
{
    long result = 1;
    while (n > 1) {
        result *= n;
        n = n - 1;
    }
    return result;
}
```

**（b）`fact_while_jm_goto`：跳转到中间版本的 `goto` 代码（对应 `-Og` 汇编的 C 翻译）：**

```c
long fact_while_jm_goto(long n)
{
    long result = 1;
    goto test;
loop:
    result *= n;
    n = n - 1;
test:
    if (n > 1)
        goto loop;
    return result;
}
```

**（c）GCC（`-Og`）实际生成的汇编代码：**

```asm
# n in %rdi
fact_while:
    movl    $1, %eax            # result = 1
    jmp     .L2                 # goto test
.L3:                            # loop:
    imulq   %rdi, %rax          # result *= n
    subq    $1, %rdi            # n = n - 1
.L2:                            # test:
    cmpq    $1, %rdi            # n > 1 ?
    jg      .L3                 # 若是，跳回 loop
    rep; ret
```

#### guarded-do

第二种翻译方法称为 **guarded-do**：先用一个条件分支来判断初始条件——若初始条件不成立就跳过整个循环，从而把代码变换成 `do-while` 循环。当使用较高的优化等级编译时（例如命令行选项 `-O1`），GCC 会采用这种策略。可以用如下模板来表达这种方法——它把通用的 `while` 循环格式翻译成 `do-while` 循环：

```c
    if (!test-expr)
        goto done;
    do
        body-statement
        while (test-expr);
done:
```

相应地，还可以把它进一步翻译成 `goto` 代码，如下所示：

```c
    if (!test-expr)
        goto done;
loop:
    body-statement
    if (test-expr)
        goto loop;
done:
```

再来看一个例子。下方代码（对应图 3-21）用与 图 3-20 相同的阶乘 C 代码，展示了 GCC 在命令行选项 `-O1` 下的编译结果：图 3-21c 给出的是实际生成的汇编代码，图 3-21b 则是这段汇编代码更易读的 C 语言表示。对照 `goto` 代码可以看到：如果 `n` 的初始值满足 `n <= 1`，就会跳过整个循环；循环本身的基本结构与该函数 `do-while` 版本（图 3-19）产生的一致。不过有一个有趣的特性：循环测试从原始 C 代码的 `n > 1` 变成了 `n != 1`。编译器知道只有当 `n > 1` 时才会进入循环，而循环体又把 `n` 递减——递减后的 `n` 只可能是 1 或更大的值，绝不会是 0；因此测试 `n != 1` 与测试 `n > 1` 在这里是等价的。

**（b）`fact_while_gd` 的 `goto` 代码（对应 `-O1` 汇编的可读 C 表示）：**

```c
long fact_while_gd(long n)
{
    long result = 1;
    if (n <= 1)
        goto done;
loop:
    result *= n;
    n = n - 1;
    if (n != 1)
        goto loop;
done:
    return result;
}
```

**（c）GCC（`-O1`）实际生成的汇编代码：**

```asm
# n in %rdi
fact_while_gd:
    movl    $1, %eax            # result = 1
    cmpq    $1, %rdi            # n 与 1 比较
    jle     .L4                 # 若 n <= 1，跳到 done
.L3:                            # loop:
    imulq   %rdi, %rax          # result *= n
    subq    $1, %rdi            # n = n - 1
    cmpq    $1, %rdi            # 测试 n != 1
    jne     .L3                 # 若 n != 1，跳回 loop
.L4:                            # done:
    rep; ret
```

### 4.3 for 循环

for 循环的通用形式如下：

```c
for (init-expr; test-expr; update-expr) 
    body-statement;
```

C 语言标准规定（有一个例外，将在练习题 3.29 中特别说明），`for` 循环的行为与下面这段等价的 `while` 循环的代码完全一致：

```c
    init-expr;
    while (test-expr) {
        body-statement
        update-expr;
    }
```

即程序首先对初始化表达式 `init-expr` 求值，随后进入循环：先对测试条件 `test-expr` 求值，若测试结果为“假”就退出循环，否则执行循环体 `body-statement`，最后对更新表达式 `update-expr` 求值，如此周而复始。

GCC 为 `for` 循环生成的代码，就是 `while` 循环两种翻译方式之一，具体采用哪一种取决于优化等级。

#### 示例

作为一个示例，考虑用 `for` 循环写的阶乘函数：

```c
long fact_for(long n)
{
    long i;
    long result = 1;
    for (i = 2; i <= n; i++)
        result *= i;
    return result;
}
```

先把 `for` 循环转换成 `while` 循环，得到下面的代码：

```c
long fact_for_while(long n)
{
    long i = 2;
    long result = 1;
    while (i <= n) {
        result *= i;
        i++;
    }
    return result;
}
```

再对 `while` 循环进行跳转到中间变换，得到如下的 `goto` 代码：

```c
long fact_for_jm_goto(long n)
{
    long i = 2;
    long result = 1;
    goto test;
loop:
    result *= i;
    i++;
test:
    if (i <= n)
        goto loop;
    return result;
}
```

而这是使用命令行选项 `-Og` 的 GCC 所产生的汇编代码：

```asm
# n in %rdi
fact_for:
    movl    $1, %eax            # result = 1
    movl    $2, %edx            # i = 2
    jmp     .L2                 # goto test
.L3:                            # loop:
    imulq   %rdx, %rax          # result *= i
    addq    $1, %rdx            # i++
.L2:                            # test:
    cmpq    %rdi, %rdx          # i <= n ?
    jle     .L3                 # 若是，跳回 loop
    rep; ret
```

综上所述，C 语言中所有三种形式的循环——`do-while`、`while` 和 `for`——都可以用同一种简单的策略翻译成包含一个或多个条件分支的机器代码。条件控制转移正是把循环翻译成机器代码的基本机制。

#### 练习题 3.29

在 C 语言中，执行 `continue` 语句会导致程序跳到当前循环迭代的结尾。因此，在处理 `continue` 语句时，「把 `for` 循环翻译成 `while` 循环」的描述规则需要做一些改进。例如，考虑下面的代码：

```c
long sum = 0;
long i;
for (i = 0; i < 10; i++) {
    if (i & 1)
        continue;
    sum += i;
}
```

A. 如果只是机械地套用「把 `for` 循环翻译成 `while` 循环」的规则，会得到什么样的结果？产生的代码又有什么错误？
B. 如何用 `goto` 语句替代 `continue` 语句，以保证 `while` 循环的行为与 `for` 循环完全一致？

**答案：**

A. 套用翻译规则会得到下面的代码：

```c
long sum = 0;
long i = 0;
while (i < 10) {
    if (i & 1)
        continue;
    sum += i;
    i++;
}
```

由于 `continue` 语句会阻止索引变量 `i` 被更新，这段代码会陷入死循环。

B. 通用的解决办法是用 `goto` 语句替代 `continue` 语句：它跳过循环体中剩余的部分，直接跳到更新（update）部分：

```c
long sum = 0;
long i = 0;
while (i < 10) {
    if (i & 1)
        goto update;
    sum += i;
update:
    i++;
}
```

## 五、switch 语句的实现

`switch`（开关）语句可以根据一个整数索引值进行多重分支（multiway branching）。在处理具有多种可能结果的测试时，这种语句特别有用：它不仅能提高 C 代码的可读性，还能借助 **跳转表**（jump table）这一数据结构让实现更加高效。

跳转表是一个数组，其中第 `i` 个表项是一个代码段的地址，该代码段实现的是当开关索引值等于 `i` 时程序应采取的动作。程序用开关索引值对跳转表做一次数组引用，从而确定跳转指令的目标。与使用一长串 `if-else` 语句相比，跳转表最大的优点是：执行 `switch` 语句所花的时间与开关情况的数量无关。GCC 会根据开关情况的数量、以及开关情况取值的稀疏程度来决定如何翻译开关语句：当开关情况数量比较多（例如 4 个以上）、且取值范围跨度较小时，就会使用跳转表。

### 5.1 示例代码

图 3-22a 是一个 C 语言 `switch` 语句的示例。这个例子有一些非常有意思的特征：情况标号（case label）覆盖了一个不连续的区域（例如情况 101 和 105 都没有对应的标号）；有些情况拥有多个标号（如情况 104 和 106）；还有些情况会落入其他情况之中（如情况 102），因为它的代码段没有以 `break` 语句结尾。

图 3-23 是编译 `switch_eg` 时产生的汇编代码，用 C 语言描述这段代码的行为，就得到图 3-22b 中的过程 `switch_eg_impl`。这段 C 代码使用了 GCC 对跳转表提供的支持，这是对 C 语言的一种扩展：数组 `jt` 包含 7 个表项，每个表项都是一个代码块的地址。这些位置由代码中的标号定义——在 `jt` 的表项里用代码指针指明，即由标号再加上 `&&` 前缀组成（为了实现这个扩展，GCC 的作者们创造了 `&&` 运算符，它用于生成一个指向代码位置的指针）。

下面是 `switch_eg` 的 C 代码（对应原书图 3-22a），以及用跳转表改写后的 `switch_eg_impl`（对应图 3-22b）：

```c
void switch_eg(long x, long n, long *dest)
{
    long val = x;

    switch (n) {
        case 100:               /* Case 100 */
            val *= 13;
            break;
        case 102:               /* Case 102 */
            val += 10;          /* 落入 case 103 */
        case 103:               /* Case 103 */
            val += 11;
            break;
        case 104:               /* Case 104 */
        case 106:               /* Case 106 */
            val *= val;
            break;
        default:
            val = 0;
    }
    *dest = val;
}
```

```c
void switch_eg_impl(long x, long n, long *dest)
{
    /* 跳转表：表项为指向各代码块的指针 */
    static void *jt[7] = {
        &&loc_A, &&loc_def, &&loc_B, &&loc_C,
        &&loc_D, &&loc_def, &&loc_D
    };

    unsigned long index = n - 100;
    long val = x;

    if (index > 6)
        goto loc_def;

    /* 多重分支 */
    goto *jt[index];

loc_A:                          /* Case 100 */
    val *= 13;
    goto done;

loc_B:                          /* Case 102 */
    val += 10;                  /* 落入 loc_C */
loc_C:                          /* Case 103 */
    val += 11;
    goto done;

loc_D:                          /* Cases 104、106 */
    val *= val;
    goto done;

loc_def:                        /* 默认分支 */
    val = 0;

done:
    *dest = val;
}
```

原始 C 代码为值 100、102–104 和 106 提供了对应的 `case`，但开关变量 `n` 本身可以是任意整数。编译器先把 `n` 减去 100，把取值范围移到 0 到 6 之间，并创建一个新的程序变量（在我们的 C 版本中称为 `index`）。利用「补码表示的负数会映射成无符号表示的大正数」这一事实，把 `index` 当作无符号值看待，可以进一步简化分支判断：只需测试 `index` 是否大于 6，就能判定它是否落在 $0\sim6$ 的范围之外。

在 C 和汇编代码中，根据 `index` 的值，共有五个不同的跳转位置：`loc_A`（在汇编代码中标识为 `.L3`）、`loc_B`（`.L5`）、`loc_C`（`.L6`）、`loc_D`（`.L7`）以及 `loc_def`（`.L8`），其中最后一个就是默认分支的目的地址。每个标号都标识着一个实现某种情况处理的代码块。在 C 和汇编两种代码中，程序都会把 `index` 与 6 比较，若大于 6 就跳转到默认代码处。

```asm
# x in %rdi, n in %rsi, dest in %rdx
switch_eg:
    subq    $100, %rsi            # index = n - 100
    cmpq    $6, %rsi              # 比较 index 与 6
    ja      .L8                   # 若 index > 6（无符号），跳转到默认分支
    jmp     *.L4(,%rsi,8)         # 间接跳转：跳到 jt[index]
.L3:                              # loc_A：Case 100
    leaq    (%rdi,%rdi,2), %rax   # rax = 3x
    leaq    (%rdi,%rax,4), %rdi   # rdi = x + 4 * rax = 13x
    jmp     .L2                   # 跳到 done
.L5:                              # loc_B：Case 102
    addq    $10, %rdi             # val += 10
.L6:                              # loc_C：Case 103
    addq    $11, %rdi             # val += 11
    jmp     .L2                   # 跳到 done
.L7:                              # loc_D：Cases 104、106
    imulq   %rdi, %rdi            # val *= val
    jmp     .L2                   # 跳到 done
.L8:                              # loc_def：默认分支
    movl    $0, %edi              # val = 0
.L2:                              # done：
    movq    %rdi, (%rdx)          # *dest = val
    ret
```

执行 `switch` 语句的关键步骤，是通过跳转表访问代码位置。在 C 代码中，这对应一条引用了跳转表 `jt` 的 `goto` 语句；而在我们的汇编代码版本里，对应操作是一条 `jmp` 指令，其操作数带有前缀 `*`，表明这是一个**间接跳转**——操作数指定一个内存位置，该位置的索引由寄存器 `%rsi` 给出，而 `%rsi` 中保存的正是 `index` 的值。

C 代码把跳转表声明为一个包含 7 个元素的数组，每个元素都是指向某个代码位置的指针。这些元素覆盖 `index` 的取值 $0\sim6$，对应着 `n` 的取值 $100\sim106$。可以看到，跳转表对重复情况的处理很简单：对表项 4 和 6 使用相同的代码标号（`loc_D`）；而对缺失情况的处理，则是对表项 1 和 5 使用默认情况的标号（`loc_def`）。

在汇编代码中，跳转表用下面的声明来表示（我们为它添加了一些注释）：

```asm
    .section .rodata
    .align   8
.L4:
    .quad    .L3    # index 0：Case 100（loc_A）
    .quad    .L8    # index 1：默认分支（loc_def）
    .quad    .L5    # index 2：Case 102（loc_B）
    .quad    .L6    # index 3：Case 103（loc_C）
    .quad    .L7    # index 4：Cases 104、106（loc_D）
    .quad    .L8    # index 5：默认分支（loc_def）
    .quad    .L7    # index 6：Cases 104、106（loc_D）
```

这些声明表明：在名为 `.rodata`（只读数据，Read-Only Data）的目标代码段中，应存放一组 7 个「四字」（每个 8 字节），其中每个字的值都是与指定汇编代码标号（例如 `.L3`）相关联的指令地址。标号 `.L4` 标记出这段分配的起始地址，与该标号相对应的地址将作为 `switch_eg` 中间接跳转的基地址。

仔细研究所有这些代码需要花费不少功夫，但关键在于领会：使用跳转表是实现多重分支的一种非常高效的方法。在我们的例子里，程序只需一次跳转表引用，就能分支到 5 个不同的位置；即便 `switch` 语句有上百种情况，也只需要一次跳转表访问即可处理。

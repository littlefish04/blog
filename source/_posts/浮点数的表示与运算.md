## 一、浮点数的表示

### 1.1 二进制小数

#### 二进制小数的表示法

考虑形如 $b_m b_{m-1} \cdots b_1 b_0 . b_{-1} b_{-2} \cdots b_{-n}$ 的表示法，其中每个二进制数字 $b_i$ 的取值都是 0 或 1。与整数的二进制表示类似，每一位都对应一个权重 $2^i$，只不过这里的指数 $i$ 可以是负数。符号「.」称为**二进制小数点**（binary point）：点左边的位是整数部分，权为 2 的正幂（$2^0, 2^1, \cdots$）；点右边的位是小数部分，权为 2 的负幂（$2^{-1}, 2^{-2}, \cdots$）。

**原理：二进制小数编码的定义**

$$b = \sum_{i=-n}^{m} b_i 2^i$$

也就是说，把每一位的取值 $b_i$ 与其权重 $2^i$ 相乘后求和，即可得到这个位模式对应的数值。例如，$101.11_2$ 表示：

$$101.11_2 = 1 \times 4 + 0 \times 2 + 1 \times 1 + 1 \times \frac{1}{2} + 1 \times \frac{1}{4} = 5\frac{3}{4}$$

可以很容易地看出，二进制小数点向左移动一位，相当于这个数被 2 除；类似地，二进制小数点向右移动一位，相当于将这个数乘以 2。

注意，形如 $0.11\cdots1_2$ 的数表示的是刚好小于 1 的数。例如，$0.111111_2$ 表示 $63/64$。我们将用简单的表达法 $1.0 - \epsilon$ 来表示这样的数值。

#### 定点表示的局限

小数的二进制表示法只能表示那些能够被写成 $x \times 2^y$ 的数，其他的值只能够被近似地表示。例如 $\frac{1}{3}$ 无法被精确表示，只能近似为无限循环的 $0.010101\cdots_2$；增加表示的长度可以提高近似的精度，却无法消除误差本身。

定点表示还有另一个局限：它无法高效地表示非常大或非常小的数。例如 $5 \times 2^{100}$，用定点表示需要写出 101 后面再跟 100 个 0，位模式长得不可接受。要解决这个问题，需要让小数点的位置能够「浮动」——这正是下一节浮点表示的核心思想。

### 1.2 IEEE 浮点表示

**IEEE 浮点标准**用以下形式来表示一个数：

**原理：IEEE 浮点表示**

$$V = (-1)^s \times M \times 2^E$$

其中三个部分各有其含义：

- **符号（sign）$s$**：决定这个数是正数还是负数。对于数值 0 的符号位，有特殊的解释规定；
- **尾数（significand）$M$**：一个二进制小数，取值范围是 $1 \sim 2 - \epsilon$（规格化的值）或 $0 \sim 1 - \epsilon$（非规格化的值）；
- **阶码（exponent）$E$**：对浮点数加权，权重是 2 的 $E$ 次幂（$E$ 可以是负数）。

浮点数的位表示被划分为三个字段，分别对这些值进行编码：

- 一个单独的**符号位 $s$** 直接编码符号 $s$；
- $k$ 位的**阶码字段** $\exp = e_{k-1} \cdots e_1 e_0$ 编码阶码 $E$；
- $n$ 位的**小数字段** $\mathrm{frac} = f_{n-1} \cdots f_1 f_0$ 编码尾数 $M$。

在单精度浮点格式（C 语言的 `float`）中，$s$、$\exp$、$\mathrm{frac}$ 三个字段分别为 1、8、23 位，构成一个 32 位的表示；在双精度浮点格式（C 语言的 `double`）中，三个字段分别为 1、11、52 位，构成一个 64 位的表示。

给定位表示，根据阶码字段的值，被编码的值可以分成三种不同的情况（最后一种情况有两个变体）。

#### 规格化的值

当阶码字段不全为 0 且不全为 1 时，属于这种情况。此时阶码字段被解释为以**偏置（bias）**形式表示的有符号整数：

$$E = e - \mathrm{Bias}$$

其中 $e$ 是阶码字段 $e_{k-1} \cdots e_1 e_0$ 的无符号数值，偏置量 $\mathrm{Bias} = 2^{k-1} - 1$（单精度为 127，双精度为 1023）。由此产生指数的取值范围，对于单精度是 $-126 \sim +127$，而对于双精度是 $-1022 \sim +1023$。

小数字段被解释为描述小数值 $f$，其中 $0 \le f < 1$，尾数定义为：

$$M = 1 + f$$

这种表示称为**隐含的以 1 开头的表示**（implied leading 1）：我们可以把 $M$ 看成一个二进制表达式为 $1.f_{n-1} f_{n-2} \cdots f_0$ 的数字。由于最高位恒为 1，它不必被显式存储，因此我们能获得额外一位的精度。

> 阶码为什么采用「偏置」编码而不是补码？因为偏置编码保持了位模式与数值之间的单调关系：**比较两个正浮点数的大小时，可以直接把它们的位表示当作无符号整数来比较**，硬件无需解码阶码即可完成比较，这使得浮点数比较运算的实现更简单高效。

#### 非规格化的值

当阶码字段全为 0 时，属于这种情况。此时阶码值为：

$$E = 1 - \mathrm{Bias}$$

尾数 $M = f$，也就是**没有隐含的 1**。非规格化数有两个用途：

- **表示数值 0**：规格化数的尾数 $M$ 总是满足 $M \ge 1$，因此无法表示 0。非规格化数中，小数字段全为 0 时得到 $M = 0$，配合符号位即可表示 $+0.0$ 和 $-0.0$（两者在某些方面被认为不同，在其他方面又相同）；
- **表示非常接近 0.0 的数**：非规格化数让数值能够从 0 平滑过渡到最小规格化数，这一性质称为**逐渐下溢**（gradual underflow），避免了数值突然「跳变」到 0。

#### 特殊值

当阶码字段全为 1 时，属于这种情况，此时又分为两个变体：

- **小数字段全为 0**：得到的值表示**无穷大**（infinity）。当 $s = 0$ 时是 $+\infty$，当 $s = 1$ 时是 $-\infty$。无穷大通常由溢出产生，比如两个极大的数相乘；
- **小数字段非零**：结果值称为 **NaN**（Not a Number，非数），通常由非法的运算产生，比如计算 $\sqrt{-1}$ 或 $\infty - \infty$。

#### 三种情况的总结

将三种情况汇总如下：

| 情况 | 阶码字段 $\exp$ | 阶码值 $E$ | 尾数 $M$ | 典型用途 |
|------|---------------|-----------|---------|---------|
| 非规格化 | 全 0 | $1 - \mathrm{Bias}$ | $f$（无隐含 1） | 表示 0 与非常接近 0 的数 |
| 规格化 | 不全 0 且不全 1 | $e - \mathrm{Bias}$ | $1 + f$（隐含 1） | 常规数值 |
| 特殊值 | 全 1 | — | 全 0 → $\infty$；非 0 → NaN | 无穷大与非数 |

掌握了这三种情况，我们就能理解浮点数位模式的实际含义；浮点数的舍入与运算规则，将在后续章节继续展开。

### 1.3 数字示例

下图展示了假定的 8 位浮点格式的示例，其中阶码位 $k = 4$、小数位 $n = 3$。根据上一节的公式，偏置量为：

$$\mathrm{Bias} = 2^{k-1} - 1 = 2^{4-1} - 1 = 7$$

![8 位浮点格式的非负浮点数值示例](1788008753269.png)

#### 从 0 到无穷大的过渡

下面以非负值为例，沿着数轴从 0 到 $+\infty$ 逐段观察这个格式能表示的数值。

**数值 0**：位模式 [0 0000 000] 表示 0。

**非规格化数**：阶码字段全为 0，此时 $E = 1 - 7 = -6$，尾数 $M = f$，只由小数字段决定：

- 最小的非规格化数 [0 0000 001]：$f = \frac{1}{8}$，值为 $V = \frac{1}{8} \times 2^{-6} = \frac{1}{512}$；
- 最大的非规格化数 [0 0000 111]：$f = \frac{7}{8}$，值为 $V = \frac{7}{8} \times 2^{-6} = \frac{7}{512}$。

**规格化数**：阶码字段不全为 0 也不全为 1，此时 $E = e - 7$，尾数 $M = 1 + f$：

- 最小的规格化数 [0 0001 000]：$e = 1$，$E = -6$，$M = 1$，值为 $V = 2^{-6} = \frac{1}{64} = \frac{8}{512}$——恰好紧挨着最大非规格化数 $\frac{7}{512}$，两者之间没有空隙；
- 位模式 [0 0111 000]：$e = 7$，$E = 0$，$M = 1$，正好表示 $1.0$；
- 最大的规格化数 [0 1110 111]：$e = 14$，$E = 7$，$M = 1 + \frac{7}{8} = \frac{15}{8}$，值为 $V = \frac{15}{8} \times 2^7 = 240$。

**无穷大**：阶码字段全为 1 且小数字段全为 0，位模式 [0 1111 000] 表示 $+\infty$。

将上述关键节点汇总成下表：

| 描述 | 位模式 | 尾数 $M$ | 阶码 $E$ | 值 |
|------|--------|---------|---------|-----|
| 0 | [0 0000 000] | 0 | — | 0 |
| 最小的非规格化数 | [0 0000 001] | $\frac{1}{8}$ | $1 - 7 = -6$ | $\frac{1}{512}$ |
| 最大的非规格化数 | [0 0000 111] | $\frac{7}{8}$ | $1 - 7 = -6$ | $\frac{7}{512}$ |
| 最小的规格化数 | [0 0001 000] | $1$ | $1 - 7 = -6$ | $\frac{1}{64} = \frac{8}{512}$ |
| 1.0 | [0 0111 000] | $1$ | $7 - 7 = 0$ | 1 |
| 最大的规格化数 | [0 1110 111] | $\frac{15}{8}$ | $14 - 7 = 7$ | 240 |
| 无穷大 | [0 1111 000] | — | — | $+\infty$ |

负数值与此完全对称：只需把符号位 $s$ 置为 1，上述数值的绝对值不变。

#### 几个值得注意的观察

- **非规格化数均匀分布**：非规格化数只由小数字段决定，因此它们均匀地分布在 0 与最小规格化数之间，间隔恰好是 $\frac{1}{512}$；
- **规格化数的间距随阶码增大**：同一阶码内，相邻规格化数的间隔为 $2^{E-3}$（$n = 3$）。例如 $E = -6$ 时间隔是 $\frac{1}{512}$，而 $E = 7$ 时间隔是 $16$（$224$ 到 $240$）。也就是说，**数值越大，相邻浮点数的绝对间隔越大**；
- **过渡是连续的**：最大非规格化数 $\frac{7}{512}$ 与最小规格化数 $\frac{8}{512}$ 无缝衔接，这正是非规格化数「逐渐下溢」设计的目的——避免 0 附近出现数值空洞；
- **最大值与无穷大**：这个格式能表示的最大有限数是 240，再往上（[0 1111 000]）就溢出为 $+\infty$。

以上便是 8 位示例格式的完整图景。实际的 `float`（$k = 8, n = 23$）与 `double`（$k = 11, n = 52$）只是把这里的 $k$、$n$ 换成更大的值，编码规则与数值过渡的规律完全一致。

这种表示具有一个有趣的属性，假如我们将图 2-35 中的值的位表达式解释为无符号整数，它们就是按升序排列的，就像它们表示的浮点数一样。

## 二、舍入

因为表示方法限制了浮点数的范围和精度，所以浮点运算只能近似地表示实数运算。因此，对于某个值 $x$，我们一般希望用系统的方法找到「最接近的」匹配值 $x'$——它可以用期望的浮点形式表示出来。这就是舍入（rounding）运算的任务。

### 2.1 IEEE 的四种舍入方式

IEEE 定义了四种舍入方式：

- **向偶数舍入（round-to-even）**：默认的舍入方式。将数字舍入到最接近的值；若恰好位于两个候选值的正中间，则舍入到**最低有效位为偶数**的那一个；
- **向零舍入（round-toward-zero）**：正数向下舍入、负数向上舍入，相当于直接朝 0 的方向截断；
- **向下舍入（round-down）**：总是朝 $-\infty$ 方向舍入，结果不大于原值；
- **向上舍入（round-up）**：总是朝 $+\infty$ 方向舍入，结果不小于原值。

> 为什么默认采用向偶数舍入？如果总是向上或向下舍入，大量数据累加时误差会系统性地偏向一侧；而「中间值舍入到偶数」让一半的中间值向上、一半向下，长期来看误差相互抵消，不会积累出统计偏差。

### 2.2 二进制下的向偶数舍入

向偶数舍入同样适用于二进制小数，规则的关键在于：**最低有效位的值 0 视为偶数，值 1 视为奇数**。

下面以保留小数点后两位（即 $\frac{1}{4}$ 精度）为例，观察向偶数舍入的工作方式：

| 原始值 | 候选值 | 舍入结果 | 说明 |
|--------|--------|---------|------|
| $10.11100_2$ | $10.11_2$、$11.00_2$ | $11.00_2$ | 恰好位于正中间，舍入到最低有效位为偶数的值 |
| $10.10100_2$ | $10.10_2$、$10.11_2$ | $10.10_2$ | 恰好位于正中间，舍入到最低有效位为偶数的值 |
| $10.11101_2$ | $10.11_2$、$11.00_2$ | $11.00_2$ | 更接近 $11.00_2$，按就近原则舍入 |
| $10.00111_2$ | $10.00_2$、$10.01_2$ | $10.01_2$ | 更接近 $10.01_2$，按就近原则舍入 |

可以看到，只有恰好位于两个候选值正中间的 $10.11100_2$ 和 $10.10100_2$ 才需要动用「向偶数」的规则：前者舍入到 $11.00_2$（最低位为 0），后者舍入到 $10.10_2$（最低位为 0）；其余情况按「更接近哪个候选值就舍入到哪个」即可。

## 三、浮点运算

### 3.1 运算规则

IEEE 标准规定，浮点数的基本运算（加、减、乘、除）必须这样计算：**先求出对应实数运算的精确结果，再按舍入规则（默认为向偶数舍入）将其舍入到最近的可表示浮点数**。也就是说，浮点运算的结果不是简单地截断，而是精确算术在有限精度下的「最接近」近似。

### 3.2 浮点运算的性质

由于每一步运算都可能引入舍入误差，浮点运算呈现出一些与整数运算不同的性质：

- **加法和乘法都满足交换律**：$x + y = y + x$、$x \times y = y \times x$，这一点与整数运算一致；
- **加法不具有结合性**：$(x + y) + z$ 与 $x + (y + z)$ 可能得到不同的结果。例如在单精度（`float`）下取 $x = 3.14$、$y = z = 10^{10}$：`float` 在 $10^{10}$ 附近的相邻数间隔为 $1024$，$3.14$ 远小于半个间隔，因此 $3.14 + 10^{10}$ 被舍入回 $10^{10}$，于是：
  - $(3.14 + 10^{10}) - 10^{10} = 0$；
  - $3.14 + (10^{10} - 10^{10}) = 3.14$。

  两种结合方式得出截然不同的结果，$3.14$ 在第一种方式中完全丢失了；
- **乘法同样不具有结合性**：例如在单精度下计算 $10^{20} \times 10^{20} \times 10^{-20}$：
  - $(10^{20} \times 10^{20}) \times 10^{-20} = +\infty$，因为中间结果 $10^{40}$ 超出了 `float` 的最大值（约 $3.4 \times 10^{38}$）而溢出；
  - $10^{20} \times (10^{20} \times 10^{-20}) = 10^{20}$，因为先算出的 $10^{20} \times 10^{-20}$ 恰好等于 $1$，之后不会再溢出；
- **加法具有单调性**：如果 $a \ge b$，那么对任意 $x$（$x$ 不是 NaN），都有 $a + x \ge b + x$。无符号或补码加法不具备这一性质——溢出回绕（wrap around）会把大数变成小数，从而破坏大小关系；浮点加法则不会出现这种「越加越小」的反常现象。

## 四、C 语言中的浮点数

C 语言提供了两种不同的浮点数据类型：`float` 和 `double`。在支持 IEEE 浮点格式的机器上，这两种类型分别对应单精度和双精度浮点。

### 4.1 类型转换规则

![78807286753](1788072867539.png)

当在 `int`、`float` 和 `double` 格式之间进行强制类型转换时，程序改变数值和位模式的原则如下（假设 `int` 是 32 位的）：

- **从 `int` 转换成 `float`**：数字不会溢出（`float` 的取值范围远大于 32 位 `int`），但是可能被舍入。原因在于 `float` 只有 24 位有效位（1 位隐含的 1 加上 23 位小数），而 32 位 `int` 最多有 31 位有效位，超出 24 位的部分无法精确保留。例如 `16777217`（即 $2^{24} + 1$）转换成 `float` 后被舍入为 `16777216.0f`；
- **从 `int` 或 `float` 转换成 `double`**：因为 `double` 有更大的范围（也就是可表示值的范围），也有更高的精度（也就是有效位数），所以能够保留精确的数值——`int` 的 31 位有效位和 `float` 的 24 位有效位都能装进 `double` 的 53 位有效位；
- **从 `double` 转换成 `float`**：因为范围要小一些，所以值可能溢出成 $+\infty$ 或 $-\infty$；另外，由于精度较小，它还可能被舍入。例如 `1e300` 超出 `float` 的上限（约 $3.4 \times 10^{38}$），转换后溢出为 $+\infty$；
- **从 `float` 或 `double` 转换成 `int`**：值将会向零舍入（直接截断小数部分）。例如 `1.999` 将被转换成 `1`，而 `-1.999` 将被转换成 `-1`。进一步来说，值可能会溢出，而 C 语言标准没有对这种情况指定固定的结果。与 Intel 兼容的微处理器指定位模式 `[100...0]`（字长为 $w$ 时的 $-2^{w-1}$）为整数不确定（integer indefinite）值。一个从浮点数到整数的转换，如果不能为该浮点数找到一个合理的整数近似值，就会产生这样一个值。因此，表达式 `(int)1e10` 会得到 `-2147483648`（即 $-2^{31}$），从一个正值变成了一个负值。

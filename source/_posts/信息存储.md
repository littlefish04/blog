## 一、字节、字长与字节顺序

### 1.1 字节与虚拟地址空间

大多数计算机使用 8 位的块——**字节**（byte）——作为最小的可寻址内存单位。机器级程序将内存视为一个非常大的字节数组，称为**虚拟内存**（virtual memory）。内存中的每个字节都由一个唯一的数字标识，这个数字称为它的**地址**（address），所有可能地址的集合就称为**虚拟地址空间**（virtual address space）。

在接下来的几章中，我们将看到编译器和运行时系统如何把存储空间划分为更易管理的单元，用来存放不同的**程序对象**（program object），即程序数据、指令和控制信息。这种划分完全是在虚拟地址空间中完成的。例如，C 语言中每个指针的值（无论它指向整数、结构体还是其他程序对象）都是某个存储块第一个字节的虚拟地址。C 编译器还会把每个指针与**类型**信息关联起来，以便根据指针值的类型生成不同的机器级代码，访问指针所指向位置存储的值。

### 1.2 字长

每台计算机都有一个**字长**（word size），指明指针数据的标称大小（nominal size）。由于虚拟地址是以一个字来编码的，对于字长为 $w$ 位的机器，虚拟地址的取值范围为 $0 \sim 2^w - 1$，程序最多可以访问 $2^w$ 个字节。

32 位机器的字长为 32 位，64 位机器的字长为 64 位。

大多数 64 位机器也可以运行为 32 位机器编译的程序，这是一种向后兼容。例如，当程序 `prog.c` 用如下伪指令编译后：

```bash
linux> gcc -m32 prog.c
```

该程序就可以在 32 位或 64 位机器上正确运行。反之，若用下述伪指令编译：

```bash
linux> gcc -m64 prog.c
```

那就只能在 64 位机器上运行。因此，我们说一个程序是 “32 位程序” 还是 “64 位程序” 时，区别在于它**如何被编译**，而不是它运行在什么类型的机器上。

### 1.3 数据类型的大小

图 2-3 展示了 C 语言各种数据类型分配的字节数：

![78661445534](1786614455340.png)

为了避免依赖“典型”大小以及不同编译器设置带来的奇怪行为，ISO C99 引入了一类数据大小固定、不随编译器和机器设置变化的数据类型，其中就包括 `int32_t` 和 `int64_t`，它们分别为 4 字节和 8 字节。使用确定大小的整数类型，是程序员精确控制数据表示的最佳途径。

程序员应该尽量让程序在不同的机器和编译器上可移植，其中一个方面就是使程序对数据类型的确切大小不敏感。许多程序在编写时都假设了图 2-3 中 32 位程序的字节分配。随着 64 位机器日益普及，将这些程序移植到新机器时，许多隐藏的对字长的依赖就会显现出来，成为错误。比如，不少程序员假设 `int` 类型的程序对象足以存储一个指针，这在大多数 32 位机器上能正常工作，但在 64 位机器上却会导致问题。

### 1.4 有符号数与无符号数

大部分数据类型默认编码为**有符号数值**，除非带上前缀关键字 `unsigned`，或对确定大小的数据类型使用了特定的无符号声明。

> 所谓“编码为有符号数值”，是指用二进制补码（two's complement）等方式表示整数：最高有效位充当符号位，其余位表示数值大小，因此既能表示正数也能表示负数。与之相对，无符号编码把全部位都用于表示非负整数，取值范围更大。

数据类型 `char` 是一个例外：尽管大多数编译器和机器把它视为有符号数，但 C 标准并不保证这一点。因此，如果需要保证一个字节的有符号数值，程序员应当使用 `signed char` 来显式声明。

### 1.5 字节顺序：大端与小端

在几乎所有的机器上，*多字节对象* 都被存储为连续的字节序列，对象的地址取所使用字节中最小的地址。表示一个对象字节的排列方式有两种通用规则：有些机器按从最低有效字节到最高有效字节的顺序存储对象，称为**小端法**（little endian）；另一些机器按从最高有效字节到最低有效字节的顺序存储，称为**大端法**（big endian）。

假设变量 `x` 的类型为 `int`，位于地址 `0x100` 处，它的十六进制值为 `0x01234567`。地址范围 `0x100~0x103` 的字节顺序取决于机器的类型：

![78662686620](1786626866208.png)

注意，在字 `0x01234567` 中，高位字节的十六进制值为 `0x01`，低位字节的值为 `0x67`。

### 1.6 阅读字节序列

当阅读表示整数数据的字节序列时，字节顺序非常重要，这通常发生在检查机器级程序时。作为一个示例，下面这行代码摘自某个文件，它给出了针对 Intel x86-64 处理器的机器级代码的文本表示：

```asm
4004d3: 01 05 43 0b 20 00 add %eax,0x200b43(%rip)
```

这一行由**反汇编器**（disassembler）生成，反汇编器是一种确定可执行程序文件所表示的指令序列的工具。我们将在第 3 章中学习更多有关这些工具的知识，以及怎样解释像这样的行。现在只需注意：十六进制字节串 `01 05 43 0b 20 00` 是一条指令的字节级表示。如果取出这个序列的最后 4 个字节 `43 0b 20 00`，并按相反的顺序写出，得到 `00 20 0b 43`；去掉开头的 0，得到值 `0x200b43`，正好是右边的数值。阅读小端法机器生成的机器级程序表示时，经常需要将字节按相反的顺序排列。书写字节序列的自然方式是最低有效字节在左、最高有效字节在右，这与我们通常书写数字时最高有效位在左、最低有效位在右的习惯正好相反。

## 二、字符串、代码的表示与位级运算

在讨论字符串与代码的表示之前，先来看一个工具例程 `show_bytes`：它接收任意对象的起始地址和字节长度，以十六进制形式逐字节打印该对象在内存中的表示，后面的 2.1 节将直接用到它。

```c
#include <stdio.h>

/* byte_pointer：指向 unsigned char 的指针类型，
   它让我们可以把任意数据当作"字节数组"来逐个访问 */
typedef unsigned char *byte_pointer;

/* show_bytes：打印从 start 地址开始的 len 个字节 */
void show_bytes(byte_pointer start, size_t len) {
    size_t i;
    for (i = 0; i < len; i++)
        /* %p 打印字节的地址，%.2x 以两位十六进制打印字节的值 */
        printf("%p\t0x%.2x\n", &start[i], start[i]);
    printf("\n");
}
```

这段代码的核心逻辑并不复杂：

- `byte_pointer` 是 `unsigned char *` 的类型别名。由于 `unsigned char` 恰好占用一个字节，我们可以把任意对象的内存看作"字节数组"，逐字节访问；
- 循环从 `start[0]` 遍历到 `start[len-1]`，对每个字节打印其地址（`%p`）和两位十六进制值（`0x%.2x`），时间复杂度为 O(len)；
- 调用时只需把对象的地址强制转换为 `byte_pointer` 并传入长度，例如 `show_bytes((byte_pointer)&x, sizeof(x))`。无论 `x` 是 `int`、`float` 还是结构体，`show_bytes` 都能展示它在内存中的原始字节。

### 2.1 表示字符串

C 语言中，字符串被编码为一个以 `null`（其值为 0）字符结尾的字符数组，每个字符都由某种标准编码来表示，最常见的是 ASCII 字符码。因此，如果以参数 `"12345"` 和 6（包括终止符）运行上面的 `show_bytes`，我们会得到结果 `31 32 33 34 35 00`。

请注意，十进制数字 x 的 ASCII 码恰好是 `0x3x`（例如 `'1'` 的 ASCII 码为 `0x31`），而终止字节的十六进制表示为 `0x00`。在使用 ASCII 码作为字符码的任何系统上都会得到相同的结果，与字节顺序和字长规则无关。**因此，文本数据比二进制数据具有更强的平台独立性。**

### 2.2 表示代码

考虑下面的 C 函数：

```c
int sum(int x, int y) {
    return x + y;
}
```

当我们在示例机器上编译时，会生成如下字节表示的机器代码：

```text
Linux32   55 89 e5 8b 45 0c 03 45 08 c9 c3
Windows   55 89 e5 8b 45 0c 03 45 08 5d c3
Sun       81 c3 e0 08 90 02 00 09
Linux64   55 48 89 e5 89 7d fc 89 75 f8 03 45 fc c9 c3
```

可以看到，不同机器生成的指令编码是不同的：不同的机器类型使用不同的、互不兼容的指令集和编码方式；即使是完全一样的程序，运行在不同的操作系统上也会有不同的编码规则，因此二进制代码是不兼容的。**二进制代码很少能在不同机器和操作系统组合之间移植。**

计算机系统的一个基本概念就是：从机器的角度来看，程序仅仅只是字节序列。机器并不保存关于原始源程序的任何信息，除了可能有一些用于辅助调试的表以外。在第 3 章学习机器级编程时，我们将更清楚地看到这一点。

### 2.4 C 语言中的位级运算

C 语言的一个很有用的特性就是它支持按位布尔运算。事实上，我们在布尔运算中使用的那些符号也正是 C 语言所使用的：`|` 就是 OR（或），`&` 就是 AND（与），`~` 就是 NOT（取反），`^` 就是 EXCLUSIVE-OR（异或）。以下是一些对 `char` 类型数据表达式求值的例子：

![78749214946](1787492149462.png)

> C 语言还提供了一组逻辑运算符 `||`、`&&` 和 `!`，分别对应于命题逻辑中的 OR、AND 和 NOT 运算。逻辑运算很容易与位级运算相混淆，但二者的功能完全不同：逻辑运算把任何非零参数视为 TRUE、零视为 FALSE，并返回 1 或 0；此外，`&&` 和 `||` 还具有短路求值（short-circuit evaluation）的特性，一旦结果确定就停止对后续操作数的求值。

### 2.5 掩码运算

位级运算的一个常见用法就是实现**掩码**（mask）运算。掩码是一个位模式，表示从一个字中选出的位的集合。例如，掩码 `0xFF`（最低 8 位为 1）表示一个字中的低位字节：位级运算 `x & 0xFF` 生成一个由 `x` 的最低有效字节组成的值，而其他字节都被置为 0。比如，对于 `x = 0x89ABCDEF`，该表达式将得到 `0x000000EF`。

`~0` 会生成一个全 1 的掩码，与机器的字长无关。尽管对于 32 位机器来说，同样的掩码可以写成 `0xFFFFFFFF`，但这样的代码是不可移植的——在 64 位机器上它只覆盖低 32 位，无法得到全 1 的 64 位掩码。

### 2.6 移位运算

C 语言还提供了一组**移位**运算，向左或者向右移动位模式。对于操作数 `x`，C 表达式 `x << k` 会生成一个值，相当于把 `x` 向左移动 k 位，丢弃最高的 k 位，并在右端补 k 个 0。移位量应该是一个 $0 \sim w-1$ 之间的值，超出该范围的行为是未定义的（详见下面的提示）。移位运算是从左至右结合的，所以 `x << j << k` 等价于 `(x << j) << k`。

<div class="tip">
移位量大于等于 $w$ 时，C 标准规定其行为未定义。例如在 x86 上，移位量会被截断为低 5 位（32 位数据）或低 6 位（64 位数据），`x << 32` 实际等价于 `x << 0`；而在其他机器上可能表现不同。可移植代码应避免使用超出范围的移位量。
</div>

有一个相应的右移运算 `x >> k`，但是它的行为有点微妙。一般而言，机器支持两种形式的右移：

- **逻辑右移**：在左端补 k 个 0；
- **算术右移**：在左端补 k 个最高有效位的值。

算术右移的做法看上去可能有点奇特，但是我们会发现，它对有符号整数数据的运算非常有用。

几乎所有的编译器/机器组合都对有符号数使用算术右移，且许多程序员也都假设机器会使用这种右移。另一方面，对于无符号数，右移必须是逻辑的。

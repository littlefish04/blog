## 一、什么是 OpenGL

OpenGL 本质上是一个**规范（Specification）**，它定义了一系列接口，开发者通过这些接口可以操作 GPU 完成图形渲染工作。

所谓接口，通俗来说就是规定了函数的名称、接收的参数、返回值以及函数的作用——它只告诉你"能做什么"和"怎么调用"，而不暴露内部的实现细节。对于调用者而言，只需要知道接口的定义就能使用，完全无需关心底层是如何实现的。

OpenGL 仅仅是一份规范，本身并不包含任何函数的具体实现。真正的实现代码在哪里呢？答案是在 GPU 驱动中，由各个 GPU 厂商（如 NVIDIA、AMD、Intel 等）自行完成。当我们调用 OpenGL API 时，实际执行的是厂商在驱动层编写好的函数。

由于不同厂商的实现方式各不相同，同一段 OpenGL 代码在不同平台上的表现可能会出现差异。比如某段代码在 NVIDIA 显卡上运行良好，在 AMD 显卡上却可能出现意料之外的 Bug。此外，大部分 GPU 厂商并不会开源自己的驱动代码，因此开发者通常无从得知这些函数底层的具体实现细节。

### OpenGL 的跨平台特性

既然 OpenGL 只是一套接口规范，具体实现由各个平台的厂商分别完成，那么它的跨平台特性就很好理解了：只要某个平台实现了 OpenGL 规范，OpenGL 代码就能在该平台上运行。

对于个人开发者而言，使用 OpenGL 可以方便地将应用发布到多个平台。不过需要注意的是，许多平台对 OpenGL 的实现质量并不如其原生图形 API——底层的驱动优化可能不够充分、接口使用起来也不够便捷。因此，对于大型游戏项目来说，针对不同平台分别使用各自的原生图形 API（如 Windows 上的 DirectX、Apple 平台上的 Metal）也是常见的做法。

### 为什么学习 OpenGL

你可能也听说过其他图形 API，比如 DirectX、Vulkan 等，或许还了解到这些 API 在某些方面性能更好、功能更强。那么为什么仍然选择从 OpenGL 入门呢？

除了前面提到的——Unity 的渲染管线封装自 OpenGL——另一个重要原因是：OpenGL 在一众图形 API 中是**相对最简单**的，非常适合初学者作为图形学入门的起点。

此外，许多其他图形 API 在设计上也会提供对 OpenGL 概念的兼容或封装，学好 OpenGL 所打下的基础，在后续学习其他图形 API 时同样用得上。

## 二、设置 OpenGL 和创建窗口

### 2.1 下载 GLFW 库

首先，我们需要一个简单方便的创建窗口的方法。这里使用 GLFW 库——一个专门用于创建窗口和处理输入的 C 语言库，可以在 [An OpenGL library | GLFW](https://www.glfw.org/) 官网下载。

进入网站后，点击右上角菜单栏的 `Download`，进入下图所示页面。

![78589929171](1785899291714.png)

根据需要下载 Windows 64 位或 Windows 32 位预编译包。需要注意的是，这里的 64 位和 32 位并不是指操作系统（现在的操作系统基本都是 64 位），而是指你使用该库的项目最终编译出来的应用程序是 64 位还是 32 位，下载前请先确认项目的目标平台。笔者下载的是 64 位。

### 2.2 创建 VS C++ 项目

创建一个名为 `OpenGL` 的 C++ 项目，使用空项目模板。

![78589980492](1785899804920.png)

在解决方案资源管理器顶部的工具栏中点击"显示所有文件"，就能看到项目根目录下的文件。

在项目根目录下创建 `src` 和 `Dependencies` 两个文件夹，然后在 `src` 文件夹下创建 `Application.cpp` 文件。（图里的 Application 拼写错了，不要管它）

![78589998776](1785899987760.png)

接下来再次打开 [An OpenGL library | GLFW](https://www.glfw.org/)，进入右上角菜单栏的 `Documentation` 页面，页面中给出的 `Example code` 会创建一个最简单的窗口。复制这段代码，全部粘贴到 `Application.cpp` 里。

![78590031389](1785900313897.png)

此时可以看到 `Application.cpp` 里出现了很多红色波浪线，这是编辑器给出的错误提示。原因是我们还没有把 GLFW 库添加到项目中。

### 2.3 添加库依赖

首先打开之前下载好的 GLFW 压缩包，可以看到里面有 `include` 文件夹和一堆 `lib-` 开头的文件夹。

在项目的 `Dependencies` 文件夹下创建一个新文件夹 `GLFW`，然后把 `include` 文件夹和 `lib-vc2022` 两个文件夹复制粘贴到该文件夹下。

GLFW 压缩包里提供了多个不同版本的 `lib-vc` 文件夹，除了 2022 也可以选择其他版本，都能正常使用。

![78590084788](1785900847883.png)

进入复制过来的 `lib-vc2022` 文件夹，把 `.dll` 文件和 `dll.lib` 文件删掉。这两个是动态链接时才会用到的动态库文件，我们的应用只需要静态链接，用不到它们。

删完后文件夹下应该还剩两个文件：

![78590123359](1785901233595.png)

接下来配置 VS 项目：在解决方案资源管理器中右键项目根目录，选择"属性"。

![78590050980](1785900509806.png)

进入属性页后，先把左上角的配置改为"所有配置"：

![78590133976](1785901339768.png)

然后在 `C/C++ -> 常规 -> 附加包含目录` 里写上：

```
$(SolutionDir)Dependencies\GLFW\include
```

其中 `$(SolutionDir)` 是 VS 自带的宏，表示解决方案所在的目录（本项目解决方案和项目位于同一目录，所以这里也就是项目根目录）。这一步设置的是 GLFW 库的头文件搜索目录。

接着在 `链接器 -> 常规 -> 附加库目录` 里写上：

```
$(SolutionDir)Dependencies\GLFW\lib-vc2022
```

![78590401217](1785904012174.png)

这一步设置的是链接器的库文件搜索目录。

最后在 `链接器 -> 输入 -> 附加依赖项` 里加上 `opengl32.lib` 和 `glfw3.lib`。其中 `opengl32.lib` 是 Windows 平台上用来链接 OpenGL 函数的系统库，VS 已经帮我们装好；`glfw3.lib` 则是我们下载的 GLFW 静态库。

![78590410142](1785904101423.png)

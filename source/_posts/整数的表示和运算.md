## 一、整数的编码

### 1.1 整数的两种编码

#### 无符号数的编码

假设有一种整数数据类型，其长度为 $w$ 位。我们可以将位向量写成 $\vec x$，表示整个向量。我们用一个函数 $B2U_w$（Binary to Unsigned 的缩写，长度为 $w$）来将一个长度为 $w$ 的 0、1 串映射到非负整数：

**原理：无符号数编码的定义**

$$B2U_w(\vec x) = \sum_{i=0}^{w-1} x_i 2^i$$

其中，$x_i$ 表示位向量 $\vec x$ 中第 $i$ 位的取值（0 或 1）。也就是说，将每一位的取值与其权重 $2^i$ 相乘后求和，即可得到该位向量对应的无符号数值。

在下图中，我们用指向右侧、长度为 $2^i$ 的条表示每个位的位置 $i$，即位 $x_i$ 的「权重」就是 $2^i$。每个位向量对应的数值，等于所有值为 1 的位所对应的条的长度之和。

![78763442726](1787634427267.png)

让我们来考虑一下 $w$ 位所能表示的值的范围。最小值用位向量 $[00\cdots 0]$ 表示，即整数值 0；最大值用位向量 $[11\cdots 1]$ 表示，即整数值 $UMax_w = 2^w - 1$。

无符号数的二进制表示有一个很重要的属性：每个介于 $0 \sim 2^w - 1$ 之间的数，都有唯一的 $w$ 位编码与之对应。

#### 补码编码

现在我们还需要表示负数值。有符号数在计算机中最常见的表示方式就是**补码**（two's-complement）形式。

在这个定义中，字的最高有效位被解释为负权（negative weight）。我们用函数 $B2T_w$（Binary to Two's-complement 的缩写，长度为 $w$）来表示：

**原理：补码编码的定义**

$$B2T_w(\vec x) = -x_{w-1}2^{w-1} + \sum_{i=0}^{w-2} x_i 2^i$$

与 $B2U_w$ 相比，补码编码唯一的区别在于最高有效位的权重由 $+2^{w-1}$ 变为 $-2^{w-1}$，其余各位的权重保持不变。

最高有效位 $x_{w-1}$ 也称为**符号位**，它的「权重」为 $-2^{w-1}$，是无符号表示中该位权重的相反数。符号位被设置为 1 时，表示值为负；被设置为 0 时，值为非负。

在下图中，我们用向左指的条表示符号位具有负权重。

![78763517679](1787635176799.png)

让我们来考虑一下 $w$ 位补码所能表示的值的范围。它能表示的最小值是位向量 $[10\cdots 0]$（即符号位为 1、其余所有位为 0），其整数值为 $TMin_w = -2^{w-1}$；最大值是位向量 $[01\cdots 1]$（即符号位为 0、其余所有位为 1），其整数值为 $TMax_w = 2^{w-1} - 1$。

可以看出，$B2T_w$ 是一个从长度为 $w$ 的位模式到 $TMin_w$ 和 $TMax_w$ 之间数字的映射。与无符号表示一样，在可表示的取值范围内，每个数字都有唯一的 $w$ 位补码编码。

#### 关于 $UMax_w$、$TMin_w$ 和 $TMax_w$

图 2-14 展示了不同字长下几个重要数字的位模式和数值。前三个给出的是可表示的整数的范围，用 $UMax_w$、$TMin_w$ 和 $TMax_w$ 来表示。在后面的讨论中，我们还会经常用到这三个特殊的值。如果可以从上下文中推断出 $w$，或者 $w$ 不是讨论的主要内容时，我们会省略下标 $w$，直接引用 $UMax$、$TMin$ 和 $TMax$。

![78763652705](1787636527056.png)

关于这些数字，有几点值得注意。

第一，从图 2-9 和图 2-10 可以看到，补码的范围是不对称的：$|TMin| = |TMax| + 1$，也就是说，$TMin$ 没有与之对应的正数。正如我们将会看到的，这使补码运算具有某些特殊属性，并且容易在程序中造成细微的错误。之所以存在这种不对称性，是因为一半的位模式（符号位设置为 1 的数）表示负数，而另一半（符号位设置为 0 的数）表示非负数。由于 0 属于非负数，能表示的正数也就比负数少一个。

第二，最大的无符号数值刚好比补码最大值的两倍还大 1：$UMax_w = 2TMax_w + 1$。补码表示中所有表示负数的位模式，在无符号表示中都变成了正数。图 2-14 也给出了常数 -1 和 0 的表示。注意，补码的 -1 与无符号数的 $UMax$ 具有相同的位表示——一个全 1 的串。数值 0 在两种表示方式中都是全 0 的串。

C 语言标准并没有要求必须用补码形式来表示有符号整数，但是几乎所有的机器都是这么做的。C 库中的文件 `<limits.h>` 定义了一组常量，用来限定编译器所运行的机器上各种整型数据类型的取值范围。比如，它定义了常量 `INT_MAX`、`INT_MIN` 和 `UINT_MAX`，用于描述有符号和无符号整数的范围。对于使用补码的机器，若数据类型 `int` 有 $w$ 位，这些常量就分别对应于 $TMax_w$、$TMin_w$ 和 $UMax_w$ 的值。

### 1.2 多种整型数据类型的取值范围

C 语言支持多种**整型**数据类型，用于表示有限范围内的整数。每种类型都能用关键字来指定大小，这些关键字包括 `char`、`short`、`long`，同时还可以指示被表示的数字是非负数（声明为 `unsigned`）还是可能为负数（默认）。为这些不同大小分配的字节数，会根据程序编译为 32 位还是 64 位而有所不同。因此，不同大小所能表示的值的范围也各不相同。

C 语言标准定义了每种数据类型必须能够表示的最小取值范围。如图 2-11 所示，这些取值范围与图 2-9 和图 2-10 所示的典型实现相同或更小。固定大小的数据类型则保证其取值范围与图 2-9 给出的典型数值一致。

![78763158565](1787631585657.png)

#### 关于确定大小的整数类型

对于某些程序来说，用某个确定大小的表示来编码数据类型非常重要。我们前面看到了，某些 C 数据类型，特别是 `long` 型，在不同的机器上有不同的长度位数和取值范围，而实际上 C 语言标准只指定了每种数据类型的最小范围，而不是确定的范围。

ISO C99 标准在文件 `stdint.h` 中引入了一个整数类型类。它们的声明形如 `intN_t` 和 `uintN_t` ，对不同的 N 值指定 N 位有符号和无符号整数。N 的具体值与实现相关，但是大多数编译器允许的值为 8 、16 、32 和 64 。因此，通过将变量的类型声明为 `uint6_t` ，我们可以无歧义地声明一个 16 位无符号变量，而如果声明为 `int32_t` 就是一个 32 位有符号变量。

这些数据类型对应着一组宏，定义了每个 N 的值对应的最小和最大值。这些宏名字形如 `INTN_MIN` 、 `INTN_MAX` 和 `UINTN_MAX` 。

## 二、有符号数和无符号数的转换

### 2.1 强制类型转换

#### 位模式不变，数值改变

C 语言允许在各种不同的数字数据类型之间做强制类型转换。例如，假设变量 `x` 声明为 `int`，`u` 声明为 `unsigned`。表达式 `(unsigned) x` 会将 `x` 的值转换成一个无符号数值，而 `(int) u` 会将 `u` 的值转换成一个有符号整数。将有符号数强制类型转换成无符号数，或者反过来，会得到什么结果呢？

考虑下面的代码：

```c
short v = -12345;
unsigned short uv = (unsigned short) v;
printf("v = %d, uv = %u\n", v, uv);
```

在一台采用补码的机器上，上述代码会产生如下输出：

```
v = -12345, uv = 53191
```

`-12345` 的 16 位补码表示与 `53191` 的 16 位无符号表示是完全一样的。我们看到，强制类型转换的结果保持位值不变，只是改变了解释这些位的方式。

类似的，考虑下面的代码：

```c
unsigned u = 4294967295u;	// UMax
int tu = (int) u;
printf("u = %u, tu = %d\n", u, tu);
```

在一台采用补码的机器上，上述代码会产生如下输出：

```
u = 4294967295, tu = -1
```

对于 32 位字长来说，无符号形式的 `4294967295`（即 $Umax_{32}$）和补码形式的 `-1` 的位模式是完全一样的。将 `unsigned` 强制类型转换成 `int`，底层的位表示保持不变。

**对于大多数 C 语言的实现，处理同样字长的有符号数和无符号数之间相互转换的一般规则是：数值可能会改变，但是位模式不变。**

#### 补码转换为无符号数

对于在范围 $TMin_w \le x \le TMax_w$ 内的补码值 $x$，函数 $T2U_w$ 将其转换为无符号数：

$$T2U_w(x) = \begin{cases} x, & x \ge 0 \cr x + 2^w, & x < 0 \end{cases}$$

也就是说，非负数的补码值与其无符号值相同；负数则需要加上 $2^w$，例如 $T2U_w(-1) = -1 + 2^w = 2^w - 1 = UMax_w$。

![78772069134](1787720691349.png)

#### 无符号数转换为补码

反过来，对于在范围 $0 \le u \le UMax_w$ 内的无符号值 $u$，函数 $U2T_w$ 将其转换为补码：

$$U2T_w(u) = \begin{cases} u, & u \le TMax_w \cr u - 2^w, & u > TMax_w \end{cases}$$

也就是说，不超过 $TMax_w$ 的无符号值保持原样；超过 $TMax_w$ 的值则需要减去 $2^w$，例如 $U2T_w(UMax_w) = UMax_w - 2^w = -1$。

#### 总结

![78772079723](1787720797239.png)

总结一下，我们考虑无符号与补码表示之间互相转换的结果。对于在范围 $0 \le x \le TMax_w$ 之内的值 $x$ 而言，我们得到 $T2U_w(x) = x$ 和 $U2T_w(x) = x$。也就是说，在这个范围内的数字有相同的无符号和补码表示。对于这个范围以外的数值，转换需要加上或者减去 $2^w$。例如，我们有 $T2U_w(-1) = -1 + 2^w = UMax_w$——最靠近 0 的负数映射为最大的无符号数。在另一个极端，我们可以看到 $T2U_w(TMin_w) = -2^{w-1} + 2^w = 2^{w-1} = TMax_w + 1$——最小的负数映射为一个刚好在补码的正数范围之外的无符号数。

### 2.2 显式和隐式转换

通常，大多数数字都默认为是有符号的。例如，当声明一个像 `12345` 或者 `0x1A2B` 这样的常量时，这个值就被认为是有符号的。要创建一个无符号常量，必须加上后缀字符 `U` 或者 `u`，例如 `12345U` 或者 `0x1A2Bu`。

C 语言允许无符号数和有符号数之间的转换。虽然 C 标准没有精确规定应如何进行这种转换，但大多数系统遵循的原则是底层的位表示保持不变。显式的强制类型转换就会导致转换发生，就像下面的代码：

```c
int tx, ty;
unsigned ux, uy;

tx = (int) ux;
uy = (unsigned) ty;
```

另外，当一种类型的表达式被赋值给另外一种类型的变量时，转换是隐式发生的，就像下面的代码：

```c
int tx, ty;
unsigned ux, uy;

tx = ux; /* Cast to signed */
uy = ty; /* Cast to unsigned */
```

#### 打印时的隐式转换

当用 `printf` 输出数值时，分别用指示符 `%d`、`%u` 和 `%x` 以有符号十进制、无符号十进制和十六进制格式输出一个数字。注意 `printf` 没有使用任何类型信息，所以它可以用指示符 `%u` 来输出类型为 `int` 的数值，也可以用指示符 `%d` 输出类型为 `unsigned` 的数值。

```c
int x = -1;
unsigned u = 2147483648; /* 2 to the 31st */
printf("x = %u = %d\n", x, x);
printf("u = %u = %d\n", u, u);
```

当在一个 32 位机器上运行时，它的输出如下：

```
x = 4294967295 = -1
u = 2147483648 = -2147483648
```

#### 运算中的隐式转换

当执行一个运算时，如果它的一个运算数是有符号的而另一个是无符号的，那么 C 语言会隐式地将有符号参数强制类型转换为无符号数，并假设这两个数都是非负的，来执行这个运算。

- 这种方法对于像 `<` 和 `>` 这样的关系运算符来说，会导致非直观的结果。图 2-19 展示了一些关系表达式的示例以及它们得到的求值结果，这里假设数据类型 `int` 表示为 32 位补码。

  ![78772197274](1787721972745.png)

  > 为什么把 $TMin_{32}$ 写为 `-2147483647 - 1` 而不是 `-2147483648`？因为字面常量 `2147483648` 已经超出了 `int` 的表示范围（$TMax_{32} = 2147483647$），编译器会把它当作更宽的类型处理，导致整个表达式的类型不再是 `int`。而 `-2147483647 - 1` 全程都是 `int` 运算：先取 $TMax_{32}$ 的相反数，再减 1，结果恰好是 $TMin_{32} = -2147483648$，既不会溢出，也保证了表达式的类型为 `int`。

- 被隐式转换为无符号数的减法会导致什么结果？**结果永远是非负的**。原因在于，无符号算术是模 $2^w$ 的运算，计算结果始终落在 $[0, 2^w - 1]$ 范围内。当减法结果小于 0 时会发生「回绕」（wrap around），从 $2^w - 1$ 一端重新出现。例如 `0U - 1`：`1` 先被隐式转换为无符号数，计算 $0 - 1 \bmod 2^{32} = 4294967295$，得到的是 $UMax_{32}$ 而非负数。因此，只要运算中混入了无符号数，减法结果就不可能小于 0，这常常是程序中难以察觉的 bug 来源。

## 三、扩展和截断数字

### 3.1 扩展一个数字的位表示

一个常见的运算是在不同字长的整数之间转换，同时又保持数值不变。当然，当目标数据类型太小以至于不能表示想要的值时，这根本就是不可能的。然而，从一个较小的数据类型转换到一个较大的类型，应该总是可能的。

#### 零扩展和符号扩展

要将一个无符号数转换为一个更大的数据类型，我们只要简单地在表示的开头添加 0。这种运算被称为**零扩展**（zero extension）。

要将一个补码数字转换为一个更大的数据类型，可以执行一个**符号扩展**（sign extension），在表示中添加最高有效位的值。

例如，考虑下面的代码：

```c
short sx = -12345;			/* -12345 */
unsigned short usx = sx;	/* 53191 */
int x = sx;					/* -12345 */
unsigned ux = usx;			/* 53191 */

printf("sx = %d: \t", sx);
show_bytes((byte_pointer) &sx, sizeof(short));
printf("usx = %u:\t", usx);
show_bytes((byte_pointer) &usx, sizeof(unsigned short));
printf("x = %d: \t", x);
show_bytes((byte_pointer) &x, sizeof(int));
printf("ux = %u:\t", ux);
show_bytes((byte_pointer) &ux, sizeof(unsigned));
```

在采用补码表示的 32 位大端法机器上运行这段代码时，打印出如下输出：

```
sx = -12345: cf c7
usx = 53191: cf c7
x = -12345: ff ff cf c7
ux = 53191: 00 00 cf c7
```

我们看到，尽管 `-12345` 的补码表示和 `53191` 的无符号表示在 16 位字长时是相同的，但是在 32 位字长时却是不同的。前者使用的是符号扩展——在开头添加的 16 位都是最高有效位 1，表示为十六进制就是 `0xFFFF`；后者则用 16 个 0 来扩展，表示为十六进制就是 `0x0000`。

图 2-20 给出了从字长 $w = 3$ 到 $w = 4$ 的符号扩展的结果。

![78772495664](1787724956647.png)

#### 转换的先后顺序

值得一提，从一个数据大小到另一个数据大小的转换，以及无符号和有符号数字之间的转换的相对顺序，能够影响一个程序的行为。考虑下面的代码：

```c
short sx = -12345;
unsigned uy = sx;

printf("uy = %u:\t", uy);
show_bytes((byte_pointer) &uy, sizeof(unsigned));
```

在一台大端法机器上，这部分代码产生如下输出：

```
uy = 4294954951: ff ff cf c7
```

这表明当把 `short` 转换成 `unsigned` 时，我们先要改变大小，之后再完成从有符号到无符号的转换。也就是说，`(unsigned) sx` 等价于 `(unsigned)(int) sx`，求值得到 4294954951，而不等价于 `(unsigned)(unsigned short) sx`，后者求值得到 53191。事实上，这个规则是 C 语言标准要求的。

### 3.2 截断数字

假设我们不用额外的位来扩展一个数值，而是减少表示一个数字的位数。例如下面代码中这种情况：

```c
int x = 53191;
short sx = (short) x;	/* -12345 */
int y = sx;				/* -12345 */
```

当我们把 `x` 强制类型转换为 `short` 时，我们就将 32 位的 `int` 截断为 16 位的 `short int`。这个 16 位的位模式就是 `-12345` 的补码表示。当我们把它强制类型转换回 `int` 时，符号扩展把高 16 位设置为 1，从而生成 `-12345` 的 32 位补码表示。

当将一个 $w$ 位的数截断为一个 $k$ 位数字时，我们会丢弃高 $w - k$ 位，得到一个新位向量。截断一个数字可能会改变它的值——溢出的一种形式。

对于一个无符号数，我们可以很容易得出其数值结果：

**原理：无符号数截断到 $k$ 位**

$$x' = x \bmod 2^k$$

该原理背后的直觉是：所有被截去的位，其权重都为 $2^i$ 的形式，其中 $i \ge k$。因此，每一个权重在取模操作下结果都为零。

补码截断也具有相似的属性，只不过要将最高位转换为符号位：

**原理：补码截断到 $k$ 位**

$$x' = U2T_k(x \bmod 2^k)$$

在这个公式中，$x \bmod 2^k$ 将是 0 到 $2^k - 1$ 之间的一个数。对其应用函数 $U2T_k$ 产生的效果是把最高有效位 $x_{k-1}$ 的权重从 $2^{k-1}$ 转变为 $-2^{k-1}$。举例来看，将数值 $x = 53191$ 从 `int` 转换为 `short`。由于 $2^{16} = 65536 \ge x$，我们有 $x \bmod 2^{16} = x$。但是，当我们把这个数转换为 16 位的补码时，我们得到 $x' = 53191 - 65536 = -12345$。

## 四、整数运算

在前几节我们讨论了无符号数和补码的编码方式，这一节我们来看看这些编码之上的算术运算——加法、减法、乘法与除法。在展开之前，有两个重要的观察值得先记住：

- 整数运算的结果可以完全由**低 $w$ 位**决定，高位对结果没有影响；
- 无符号数和补码的加法、减法、乘法，本质上是**同一种模 $2^w$ 算术**，只是对结果的解释方式不同。

### 4.1 无符号加法

让我们为参数 $x$ 和 $y$ 定义运算 $+_w^u$， 其中 $0 \le x, y < 2^w$，该操作是把 $x+y$ 截断为 $w$ 位得到的结果，再把这个结果看做是一个无符号数。

**原理：无符号加法**

考虑两个 $w$ 位的无符号数 $x$、$y$，满足 $0 \le x, y < 2^w$。它们的数学和介于 $0$ 与 $2^{w+1} - 2$ 之间，最多需要 $w + 1$ 位来表示。丢弃结果的最高位，就得到模 $2^w$ 的加法：

$$x +_w^u y = (x + y) \bmod 2^w$$

可以看到，当 $x + y \ge 2^w$ 时，和的 $w+1$ 位表示中的最高位会等于 1，因此丢弃它就相当于从和中减去 $2^w$，而后落在 $[0, 2^w - 1]$ 的范围内。例如在 4 位无符号表示中，$9 + 12 = 21 \ge 16$，于是 $9 +_4^u 12 = 21 \bmod 16 = 5$，与我们熟悉的 $9 + 12 = 21$ 相去甚远。

说一个算术运算**溢出**，是指完整的整数结果不能放到数据类型的字长限制中去。对现在的情况来说，当两个运算数的和为 $2^w$ 或者更大时，就发生了溢出。

C 语言中**无符号数的溢出是「定义良好」的**，结果就是模 $2^w$ 的值：

```c
unsigned x = 4294967295u;	/* UMax_32 */
unsigned y = 1;
unsigned s = x + y;			/* s = 0，回绕到 0 */
```

#### 无符号加法的溢出检测

由于溢出时结果必然小于任一个运算数（$s = x + y - 2^w < x$ 且 $s < y$），检测只需一次比较：

```c
/* 无符号加法 x + y 是否溢出：不溢出返回 1，溢出返回 0 */
int uadd_ok(unsigned x, unsigned y) {
    unsigned s = x + y;
    return s >= x;	/* 溢出时必有 s < x（同时也有 s < y） */
}
```

**可以看到**，`uadd_ok` 只做了一次加法和一次比较，时间复杂度为 O(1)，这也是实践中检测无符号加法溢出的常见写法。

#### 无符号加法的逆操作

让我们考虑 $w$ 位的无符号数的集合，执行加法运算 $+_w^u$。对于每个值 $x$，必然有某个值 $-_w^u x$ 满足 $-_w^u x +_w^u x = 0$。该加法的逆操作可以表述如下：

**原理：无符号数求反**

对满足 $0 \le x < 2^w$ 的任意 $x$，其 $w$ 位的无符号逆元 $-_w^u x$ 由下式给出：

$$-_w^u x = \begin{cases} 0, & x = 0 \cr 2^w - x, & x > 0 \end{cases}$$

当 $x=0$ 时，加法逆元显然是 0。对于 $x > 0$，考虑值 $2^w - x$。我们观察到这个值在 $0 < 2^w - x < 2^w$ 的范围之内，并且 $2^w - x +_w^u x = 0$。因此，它就是 $x$ 在 $+_w^u$ 下的逆元。

### 4.2 补码加法

有符号数的加法要复杂一些：补码的范围不对称（$|TMin_w| = |TMax_w| + 1$），而且溢出分为正溢出和负溢出两种情况。

**原理：补码加法**

对于 $TMin_w \le x, y \le TMax_w$ 的补码数 $x$、$y$，定义：

$$x +_w^t y = \begin{cases} x + y - 2^w, & x + y \ge 2^{w-1} \cr x + y, & -2^{w-1} \le x + y < 2^{w-1} \cr x + y + 2^w, & x + y < -2^{w-1} \end{cases}$$

直观地理解，补码加法可以看作：先把两个数当作无符号数相加（即模 $2^w$ 加法），再把结果的低 $w$ 位按补码解释。条件 $x + y \ge 2^{w-1}$ 对应**正溢出**，条件 $x + y < -2^{w-1}$ 对应**负溢出**，中间情况结果正常。下面以 4 位补码（范围 $[-8, 7]$）为例：

- $5 +_4^t 5$：$10 \ge 8$，正溢出，结果为 $10 - 16 = -6$；
- $-8 +_4^t (-8)$：$-16 < -8$，负溢出，结果为 $-16 + 16 = 0$；
- $7 +_4^t 1$：$8 \ge 8$，正溢出，结果为 $8 - 16 = -8$——两个正数相加，却得到了最小的负数。

#### 补码加法的溢出检测

补码加法的溢出检测规则：**正溢出当且仅当两个运算数都为正而结果非正；负溢出当且仅当两个运算数都为负而结果非负**。

```c
/* 补码加法 x + y 是否溢出：不溢出返回 1，溢出返回 0 */
int tadd_ok(int x, int y) {
    int s = x + y;
    if (x > 0 && y > 0 && s < 0)
        return 0;	/* 正溢出 */
    if (x < 0 && y < 0 && s >= 0)
        return 0;	/* 负溢出 */
    return 1;
}
```

为什么可以这样判断？因为只有同号相加才可能溢出：两个正数相加，正常结果必然为正，一旦结果变成负数，说明结果回绕了 $2^w$，即发生了正溢出；负数的情况完全对称。

> 需要提醒的是，C 标准规定**有符号整数的溢出是未定义行为**（undefined behavior）。上面的检测依赖「结果回绕」的机器行为，而开启优化的编译器可能假设溢出不会发生。因此 `tadd_ok` 更适合作为理解硬件行为的学习示例；在工程代码中，建议优先使用 `__builtin_add_overflow` 这类编译器内建函数。

#### 补码加法的逆运算

**原理：补码的非**

对任意补码值 $x$，它的加法逆元（取负）定义为：

$$-_w^t x = \begin{cases} TMin_w, & x = TMin_w \cr -x, & x > TMin_w \end{cases}$$

唯一特殊的是 $TMin_w$：由于补码范围不对称（$|TMin_w| = |TMax_w| + 1$），$TMin_w$ 没有对应的正数，而 $TMin_w  + TMin_w = -2^w + 2^w = 0$，发生负溢出结果为 0，所以它的「非」就是它自己。例如 4 位补码中，$-8$（$[1000]$）取负后仍是 $-8$。

#### 补码非的位级表示

第一种方法最常用：**按位取反再加一**。把每一位 0 变 1、1 变 0，然后整体加 1。例如 4 位补码中 $x = -5 = [1011]$：按位取反得 $[0100]$，再加一得 $[0101] = 5$，与 $-(-5) = 5$ 一致。

第二种方法：**找到最右边的 1**，该位及其右边的位保持不变，左边的所有位取反。例如 $x = 5 = [0101]$，最右边的 1 位于第 0 位，其左边是 $[010]$，取反得 $[101]$，于是结果为 $[1011] = -5$。

两种方法在原理上相通：$x + (\sim x) = -1$（全 1 的位串），两边加 1 即得 $\sim x + 1 = -x$。

另外，**减法可以看作加上相反数**：$x - y = x + (-y)$。因此减法的结果与溢出行为完全由加法和取负决定，不需要单独讨论。

### 4.3 无符号乘法

**原理：无符号乘法**

两个 $w$ 位的无符号数相乘，数学乘积最多需要 $2w$ 位来表示。与加法一样，C 语言只保留结果的低 $w$ 位：

$$x *_w^u y = (x \cdot y) \bmod 2^w$$

例如 4 位无符号表示中，$5 *_4^u 5 = 25 \bmod 16 = 9$，$12 *_4^u 7 = 84 \bmod 16 = 4$。

无符号乘法的溢出检测比加法麻烦：结果可能大于也可能小于运算数，没有「结果小于运算数」这样简单的判据。实用的做法是**用更宽的类型计算后再比较**：

```c
/* 无符号乘法 x * y 是否溢出：不溢出返回 1，溢出返回 0 */
int umul_ok(unsigned x, unsigned y) {
    unsigned long long p = (unsigned long long) x * y;
    return p <= UINT_MAX;	/* UINT_MAX 定义于 <limits.h> */
}
```

### 4.4 补码乘法

**原理：补码乘法**

与补码加法类似，补码乘法先按无符号乘法计算（模 $2^w$），再把结果的低 $w$ 位按补码解释：

$$x *_w^t y = U2T_w((x \cdot y) \bmod 2^w)$$

例如 4 位补码中 $x = -5 = [1011]$、$y = 3 = [0011]$：按无符号相乘 $11 \times 3 = 33$，模 16 得 $1$，再经 $U2T_4$ 解释仍为 $1$。于是 $-5 *_4^t 3 = 1$——负数与正数相乘，结果却是正数，这正是溢出造成的。

#### 无符号和补码乘法的位级等价性

**一个重要的性质：无符号乘法和补码乘法在低 $w$ 位上的位模式完全相同。** 也就是说，无论把同一段位模式解释为无符号数还是补码数，截断后得到的 $w$ 位乘积都一样。

作为说明，图 2-27 给出了不同 3 位数字的乘法结果。对于每一对位级运算数，我们执行无符号和补码乘法，得到 6 位的乘积，然后再把这些乘积截断到 3 位。

这正是编译器敢于把「有符号乘法」编译成与「无符号乘法」相同机器指令的原因——对低 $w$ 位而言两者没有区别。

### 4.5 乘以常数

乘法指令在早期的机器上相当昂贵，编译器因而会**把乘以常数优化为移位与加减法的组合**。核心观察是：**一个数左移 $k$ 位等于它乘以 $2^k$**：

$$x \cdot 2^k = x \ll k$$

因此任意「乘以常数」都可以分解为若干个移位与加减法：

- $x \times 3 = (x \ll 1) + x$，因为 $3 = 2 + 1$；
- $x \times 7 = (x \ll 3) - x$，因为 $7 = 8 - 1$；
- $x \times 14 = (x \ll 4) - (x \ll 1)$，因为 $14 = 16 - 2$。

编译器会挑选「移位 + 加减」次数最少的分解方式。**这种优化对无符号数和补码数都成立**：移位运算与编码方式无关，而模 $2^w$ 乘法对两种编码给出相同的低 $w$ 位结果（因为无符号和补码乘法的位级等价性）。

### 4.6 除以 2 的幂

整数除法比乘法麻烦，因为结果需要舍入。这里只讨论除以 2 的幂这一特例（编译器对除以任意常数采用的是另一套基于「乘以魔数」的技术，超出本节范围）。

#### 无符号数除以 2 的幂：逻辑右移

对于无符号数，`x >> k` 是逻辑右移（高位补 0），等价于**向下取整**的除法：

$$\lfloor x / 2^k \rfloor = x \gg k$$

例如 8 位无符号数 $x = 14 = [00001110]$，$14 \gg 2 = [00000011] = 3 = \lfloor 14/4 \rfloor$。

#### 补码除以 2 的幂：算术右移 + 偏置

对于补码数，`x >> k` 是算术右移（高位补符号位），结果等价于**向下取整**的除法。但 C 语言的 `/` 运算符要求**向零舍入**：正数向下取整，负数向上取整。两者在负数上不一致——例如 $x = -3$（8 位补码 $[11111101]$），$-3 \gg 1 = [11111110] = -2$，而 $-3 / 2$ 向零舍入应为 $-1$。

解决办法是**先加偏置再右移**：对负数先加上 $2^k - 1$，再做算术右移，就把「向下取整」修正为「向零舍入」：

$$\lceil x / 2^k \rceil = (x + 2^k - 1) \gg k, \quad x < 0$$

偏置技术利用如下属性：对于整数 $x$ 和 $y ( y > 0 )$，$\lceil x / y \rceil = \lfloor (x + y - 1) / y \rfloor$。

验证上面的例子：$(-3 + 1) \gg 1 = (-2) \gg 1 = -1$，正确。写成 C 代码：

```c
/* 补码除以 2 的幂，向零舍入（假设采用算术右移） */
int divide_power2(int x, int k) {
    int bias = (x >> 31) & ((1 << k) - 1);	/* x < 0 时 bias = 2^k - 1，否则为 0 */
    return (x + bias) >> k;
}
```

当 $x \ge 0$ 时 `bias` 为 0，退化为普通的算术右移；当 $x < 0$ 时 `bias = 2^k - 1`，实现「先加偏置再右移」。

> 注意：除法不具备乘法的代数性质。例如除法不满足分配律——$(x + y) / 2^k \ne x / 2^k + y / 2^k$，这类看似合理的化简在整数除法中并不总是成立。因此编译器对除法的优化远比对乘法谨慎，我们在手写「优化」时也要格外小心。
